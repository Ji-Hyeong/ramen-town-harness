# 완성 육수를 남겨 두는 보관함

2026-11-02. 기존에는 완성 육수60개가 차면 새로운 배합을 개발할 수 없었다.
이미 만든 메뉴·개정 비교·최고 성적이 배합을 참조하므로, 오래된 배합을 지워
공간을 만드는 방식은 안전하지 않았다. **완성 배합을 유지하면서 작업 노트와
보관함을 나누는 방식**을 구현했다. 실제 화면 검증은 최종 앱 승인 대기 중이다.

## 플레이에서 달라지는 점

육수 개발실의 육수 목록에서 `작업 노트`와 `보관함`을 고를 수 있다. 작업 노트는
60개, 전체 완성 배합은300개까지 보관한다. 페이지당6개씩 보여 주며 기존 개발
순서와 식별을 유지한다. 이 한도는 정리 공간이며 의미 있게 다른300요리의 증거는 아니다.

- `보관`하면 현재 그릇·판매 메뉴·과거 기록을 유지하며 새 개발 공간이 열린다.
- `꺼내기`는 무료이며, 작업 노트가 가득 차면 이유와 `작업 노트 보기`를 제공한다.
- 보관한 육수도 `담기`로 그대로 사용할 수 있다. 다시 만들거나 몰래 비용을 내지 않는다.
- 새 배합의 개발비는 실제 우림 완료 때 한 번 결제하고, 그릇에 담기는 별도 선택이다.

작업 노트를 정리해도 완성 배합 소유권이나 기억한 궁합은 지우지 않는다.
재료 배합 칸은 기존 가게 랭크 규칙에 따라 열린다. 이번에는 육수 목록의 정리에
집중하고 기존 공법·가격·영업·다른 성장 규칙을 유지했다.

## 저장과 실제 경로

저장21은 `broth_shelf.archived`에 완성 배합의 정규 해시만 추가한다. 원래 완성
배합 배열은 유지하므로 과거 메뉴의 배합과 숫자 인덱스가 바뀌지 않는다.
이전1~20은 빈 보관함으로 이행하며 원래 모든 값을 유지한다. 첫21저장 전에
실제20원본을 그대로 백업하는 것도 확인했다. 이전20이하의60배합 문법은 유지해,
버전 숫자만 낮춘 큰 목록을 허용하지 않는다.

실제 새 원재료 게임에서 영업3회로 비용을 충당하고 육수60개를 직접 제조·시식했다.
60개의 유료 개정이 한 메뉴 가족에 남은 상태에서 현재 육수를 보관하고61번째
우림을 완료했다. 기존60기록·개정 비교·최고 성적과 원래60배합은 그대로다.
보관한 판매 메뉴로 실제 영업 정산도 통과했다. 합성 자금·등급·기록을 주입한
경로가 아니다. 제조·영업 시계는 시험을 위해 앞당겼다.

전체300개·301개 문서의 한도 검사는 별도 합성 자료다. 실제로300배합을 만들었다거나
재미·6~10시간 본편이 완성됐다는 증거로 쓰지 않는다.

별도 읽기 전용 진단12확인으로 작업 칸을59개만 채워 한 칸 비운 상태에서도
전체300소유 한도가 새 우림을 막는지 확인했다. 자금·중복·재료 조건은 충족했고
기존 육수의 보관·복귀는 계속 가능했다. 작업 칸60한도가 전체 한도 검사를 대신
가려 주지 않도록 분리한 합성 경계 검사다. 실제 플레이 수량의 증거로 쓰지 않는다.
