# 카이로소프트 화면 연구와 UI/UX 재설계

2026-10-23 · 대상: Godot 네이티브 라멘 아틀리에, iPhone 세로 화면.

**현재 판정: 사용자가 설치본0.13의 UI/UX를 거부했다. 개선 필요.**
기존 배치·기능 검사 통과와 별개다. 직원·성장 기능 추가보다 화면 구조와
조작 흐름을 먼저 고친다. 이 문서는 조사·진단·시안의 체크포인트이며,
새 화면 구현이나 사용성 개선 완료를 뜻하지 않는다.

## 실제로 확인한 범위

카이로소프트 공식 사이트의 다섯 작품에서 공개한 화면을 직접 열어 봤다.
아래는 관찰한 구성과, 이를 우리 게임에 적용하려는 해석을 구분한 기록이다.
게임을 구매하거나 직접 플레이한 것은 아니다. 스크린샷으로 조작 횟수,
반응 시간, 애니메이션 타이밍, 실제 터치 사용성까지 확인했다고 주장하지 않는다.
공개 화면에는 구형 세로 버전과 가로 버전, 홍보용 합성 이미지가 섞여 있다.

원본 이미지의 주소·해시·관찰 용도는 로컬 연구 폴더의
`reference-manifest.json`에 기록했다. 제목 화면, 장식용 작은 GIF,
중복 페이지 캡처는 실제 조작 화면의 근거에서 제외했다.
타사 캡처는 비공개 연구 자료로만 보관하며 저장소나 게임 에셋에 포함하지 않는다.
공식 화면에서도 작은 글자와 조밀한 배치가 보인다. 이를 그대로 복사하는 대신
우리의 모바일 터치 크기·가독성 검증을 별도로 수행해야 한다.

실제 거부로 별도 보존한다.

## 먼저 바꾸는 흐름

기본 흐름은 `매장 → 메뉴 개발 → 재료 선택 → 조리 → 시식 결과 → 영업 준비/다시 개발`이다.
전역 목적지 전환, 재료 편집, 부가 설명은 같은 종류의 펼침으로 취급하지 않는다.
새 기능이나 경제 규칙을 추가하는 작업도 아니다.

1. 개발 화면에서 음식, 현재 조합, 재료 선택과 실행의 관계부터 고친다.
   국물은 육수·타레·향미유, 면은 면 종류·익힘, 토핑은 분량 슬롯으로 묶는다.
   각 그룹의 상세에서 필요한 정보만 보여주고, 뒤로 가면 임시 조합과 위치를 유지한다.
2. 시작 랭크의2칸, 랭크에 따른 기존 추가 칸, 같은 토핑의 반복 분량을
   시각적으로 드러낸다. 선택/추가/빼기/상세를 서로 다른 명확한 동작으로 만든다.
   기존 데이터의 총상한4칸과 잠금 규칙을 임의로 늘리거나 줄이지 않는다.
3. 재료를 바꿀 때 그릇과 실제 계산한 비용·준비 시간이 즉시 함께 바뀐다.
   미시식 조합에 확정 점수나 거짓 궁합 보너스를 보여주지 않는다.
   잠긴 재료는 원인과 실제 획득 경로를 짧게 알리고, 탐색 이동은 조합을 보존한다.
4. 조리 중에는 해당 음식과 단계가 중심이 된다. 재료 편집/다른 작업을
   동시에 노출해 착각하게 만들지 않는다. 기존 취소·비용 확정·저장 시점을
   바꾸지 않으며 실패나 취소의 결과는 짧고 정확하게 알린다.
5. 결과의 첫 화면에 완성 음식, 실제 손님 얼굴과 한마디, 핵심 평가,
   주행동을 모은다. 긴 재료 영수증과 수치 내역만 상세로 옮긴다.
   최초 발견/재시식/저장 실패를 구분하고 이름/완성 문구를 반복하지 않는다.
6. 매장을 기준으로 돌아가기와 목적지 이동을 정리한다. 개발 스크롤 내부에
   전역8탭과 안내를 쌓는 구조를 없앤다. 아직 보지 않은 홈의 문제를
   이번 증거로 단정하지 않으며, 선택한 시안의 연결 구현 때 새로 캡처한다.

## 터치와 효과의 구현 기준

- 클릭 가능한 대상은 일관된 윤곽·눌림·선택 표시를 갖는다. 상세 아이콘도
  최소44×44 논리 픽셀의 겹치지 않는 터치 영역과 의미 있는 접근성 이름을 갖춘다.
  그림에 아이콘이 있다고 이 기준이 충족된 것은 아니다.
- 드래그를 필수로 하지 않는다. 재료/그림 위에서 미는 기존 전체 영역 스크롤을
  보존하고, 스크롤로 취소된 누름에는 추가·삭제·음향·확정 효과가 발생하지 않는다.
- 눌림, 유효한 추가/삭제, 실패, 조리 완료, 새 발견을 구별한다.
  작은 스케일/색 변화 → 재료가 그릇에 들어가는 짧은 효과 → 조리 → 인물 반응으로
  의미를 연결한다. 매 클릭마다 화면 전체를 흔들거나 과도한 폭죽을 띄우지 않는다.
- 효과는 연속 입력을 막거나 글자를 가리지 않는다. 음소거를 유지하며,
  연출만으로 결과/돈/저장이 두 번 실행되지 않는다.
- 기기의 실제 안전 영역과 글자 크기를 기준으로 재배치한다.
  정상·선택·눌림·용량 가득 참·잠금·조리·취소·저장 실패·복귀를 함께 확인한다.

## 세 가지 시각 시안

내장 Image Gen으로 실제 현재 캡처와 공식 참조 캡처를 첨부해 **각각 독립 생성**했다.
모두 같은 시작 상태(차슈1분량, 토핑2칸 중1칸 사용, 현재 재료비2200원)를
대상으로 한다. 표의 번호는 생성 요청 순서의 가정이 아니라 대화에 실제 표시된 순서다.

| 표시 번호 | 파일 / 구조 | 선택 시 먼저 검증할 가설 |
| --- | --- | --- |
| 1 | [매장 안 작업대](uiux-reset/concepts/concept-01-shop.png): 매장 맥락을 남기고 아래 작업대에서 재료를 비교한다. | 매장을 보면서도 네 가지 시작 재료와 주행동을 바로 찾을 수 있는가? |
| 2 | [단계별 조리대](uiux-reset/concepts/concept-02-steps.png): 국물→면→토핑을 한 단계씩 편집한다. | 처음 하는 사람이 현재 단계와 다음 행동을 설명 없이 이해하는가? |
| 3 | [그릇 중심 편집](uiux-reset/concepts/concept-03-map.png): 음식과 연결된 조합 그룹을 누르고 짧은 재료 행에서 추가한다. | 익숙해진 사람이 조합을 빠르게 오가며 수정할 수 있는가? |

모바일 목표는390×844이다. 실제 생성 원본은853×1844이며 변형·늘림 없이
그대로 보존했다. 이것들은 설계 방향을 고르는 이미지로, 게임 화면 캡처나
작동하는 프로토타입이 아니다. 누름 효과·스크롤·실제 비용 변화·44px 터치 영역·
안전 영역·실제 재료와 그림의 정확한 일치는 네이티브 구현에서 별도 검증해야 한다.
그림의 장식/증기/음식 모양을 곧바로 현재 규칙의 증거로 사용하지 않는다.
시안 전체를 한 장의 배경으로 넣는 방식으로 구현하지 않는다.

생성 모드, 독립 호출의 원문 프롬프트, 참조 역할, 원본 해시와 표시 순서는
[시안 기록](uiux-reset/concepts/manifest.json)과 같은 폴더의 `prompt-*.txt`에 보존한다.
타사 이미지 자체는 저장소에 포함하지 않는다.

## 다음 구현의 완료 기준

먼저 사용자가 세 시안 중 구조를 선택하거나 수정 방향을 정해야 한다.
선택 이후 기존 Godot 화면에서 매장→개발→조리→결과의 한 줄 흐름을
연결하는 범위로 구현한다. 새 직원/성장 콘텐츠는 그 이후다.

- 시작 재료 네 가지, 토핑 빈 칸/반복 추가/삭제, 실제 비용과 시식 행동을
  첫 선택 화면에서 찾을 수 있다. 상세를 보지 않아도 기본 한 그릇을 만들 수 있다.
- 뒤로/상세 복귀/탐색 복귀가 조합과 문맥을 보존한다. 비용·발견·저장 규칙,
  이전 저장 마이그레이션, 한 번만 확정되는 거래가 유지된다.
- 새 소스에서 세로/가로의 실제 렌더링과 터치를 다시 검증한다.
