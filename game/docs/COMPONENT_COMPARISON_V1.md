# 개발품 비교와 배합 개량 V1

직접 개발한 육수·면을 현재 그릇과 비교하고, 사용하거나 배합을 불러와 다시 실험한다. 새 재료나 점수 보상을 늘리는 기능이 아니라, 기존 원재료 개발의 차이를 읽고 다음 실험을 고르는 흐름이다.

1. 완성 목록은 최근 개발 순으로6개씩 표시한다. 페이지를 넘겨도 실제 개발 기록의 순서·번호·내용은 바뀌지 않는다.
2. ‘비교·개량 보기’에서 현재 사용 중인 부품과 고른 부품의 전체 배합, 원가·준비 시간·맛 기여도를 비교한다. 음수 향 기여도도 유지한다. 공법 효과는 한 번만 반영한다.
3. ‘이 라멘에 바꾸면?’은 판매가·다른 재료·토핑·익힘을 유지하고 해당 부품 하나만 교체한 예상이다. 기존 평가기로 계산한 두 그릇·맛·원가·기본 준비 시간·세 단골의 예상 시식 점수를 보여 준다. 실제 시식 기록, 영업 판매량이나 실제 대기 시간을 뜻하지 않는다.
4. ‘그릇에 담기’는 완성품을 실제 초안에 적용한다. ‘배합 불러와 개량하기’는 개발실에서 작성 중인 해당 배합만 교체한다. 현재 그릇·완성품·시식 기록·돈·날짜·샘플은 그대로이며 자동 제작도 하지 않는다. 덮어쓰는 범위를 버튼 주변에 설명한다.
5. 불러온 배합을 실제로 바꿔 제작하고, 명시적으로 사용한 뒤 시식하면 새로운 개정 기록이 생긴다. 이미 완성한 동일 배합은 기존 완성품을 재사용하므로 중복 개발비를 받지 않는다.

새 게임의 미완성 부품은 비교 기준 완제품으로 둔갑하지 않는다. 육수와 면을 모두 만들고 그릇에 담기 전에는 한 그릇 전체의 비교 점수를 제공하지 않는다. 과거 저장의 지원되는 완제품은 실제 기존 기준으로 사용할 수 있다.

배합 불러오기는 기존 작업 잠금을 따른다. 연구 샘플을 다 썼어도 이미 획득한 배합을 읽고 불러올 수 있고, 이후 제작·시식의 재고 검사는 기존 규칙대로 적용한다. 저장 실패는 숨기지 않고, 같은 상태에서 직접 저장을 재시도해도 비용을 더 쓰지 않는다.

저장 형식은17을 유지한다. 기존 개발실 초안에 배합을 보존하며 별도의 성취·비교 결과·예상 점수를 저장하지 않는다. 변경 전 main77947d5로 직접 만든 v17 저장을 고정 fixture로 사용해 기존 기록과 실제 값의 호환성을 확인한다.

이번 작업에서 Claude Code는 비교 계산·안전한 배합 불러오기·관련 도메인 시험을 구현했다. Codex는 요구사항과 경계, 화면·목록·저장/효과 연결과 실제 입력·렌더링·회귀의 독립 검증을 맡았다. Claude는 의도적으로 파일 도구만 사용했으므로 테스트 실행은 Codex의 실제 결과로 판정한다. 사용량은 실제 응답에서 확인되는 필드만 보관하며, 구독 사용률50:50을 보장하거나 API 비용 추정을 구독 청구액으로 해석하지 않는다.

실제 화면과 검증 결과는 `uiux-reset/component-comparison-v1/` 및 저장소 루트 `evidence/component-comparison-v1.json`에 기록한다. Mac 자동 입력은 물리 iPhone 터치 수락이나6~10시간의 재미·밸런스 검증을 대신하지 않는다. iPhone 설치는 이번 범위에 포함하지 않는다.

최종 검증: 새 비교373개·제면276개·육수226개·기존129테스트59,458개 검사를 통과했다. 같은354소스·패키지의 실제 Mac 화면은 비교415개·제면291개·육수235개·편집기528개, 총112장 캡처로 검증했다. 터치 이벤트49개와 QA 도구23개도 통과했다. 수락 실행 종료0·엔진 오류0이며 실행 뒤 공식 엔진의 엄격 서명 검사도 통과했다.
