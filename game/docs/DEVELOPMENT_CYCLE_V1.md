# 한 그릇 개발 흐름 V1

메뉴 개발을 네 번의 선택 화면과 완성 목록 사이에서 오가던 흐름에서, 배합을 고르고 실제로 만들고 그릇에 담는 흐름으로 연결한다. 기존 음식 그림·목재·크림색 프레임·글꼴을 유지한다. 새 콘텐츠나 저장 형식 변경은 없다.

1. **면 배합:** 밀가루·배합수·굵기·반죽을 한 화면의 선택 카드에서 고른다. 현재 면 그림과 실제 식감·향·원가·삶는 시간을 위에 고정한다. 긴 특징과 잠금 조건은 펼쳐서 본다. 작은 화면에서는 선택 부분만 스크롤하며 선택 후에도 위치를 유지한다.
2. **제조와 완성:** 실제 우림·제면이 끝나면 방금 만든 개발품과 원가·준비 시간을 보여 준다. 직접 담기 전에는 초안에 적용하지 않는다. 육수를 담고 아직 면이 없으면 면 만들기로, 면까지 담았으면 실제 그릇으로 이어진다. 완성 화면을 닫아도 하단의 ‘만든 육수/면 담기’로 돌아올 수 있다.
3. **시식과 다음 실험:** 실제 시식 결과에서 손님 얼굴·짧은 평·맛과 취향의 차이를 함께 본다. 반응 카드를 누르면 전체 평가를 펼친다. 아래 행동 버튼은 해당 손님의 반응과 연결된 육수·간·향미유·면 선택을 연다. 선택 화면을 여는 것만으로 레시피를 바꾸거나 비용을 쓰지 않는다.

향의 음수 기여도, 개발 취소, 부족한 샘플·랭크 잠금, 저장 실패와 재시도는 유지한다. 처음 보는 조합의 궁합은 기존 규칙대로 실제로 담은 뒤 확인하며, 새 화면은 미시도 조합의 궁합이나 단골 예상 점수를 공개하지 않는다. 이미 시식한 맛과 손님 취향의 비교는 다음 실험의 관찰 자료이며 정답 레시피나 점수 보장을 뜻하지 않는다.

Claude Code가 같은 화면의 면 선택·미리보기와 제면 화면 시험을 구현했고, Codex가 간결한 배치 보정, 완성·다음 작업 연결, 시식 반응, 통합·독립 검증을 맡았다. 첫 구현의 긴 두 열 목록은 반려하고 같은 작업의 구체적 수정 요청으로 한 줄 선택 카드로 줄였다. 두 구현자를 동시에 파일에 쓰게 하지 않았다. Claude는 파일 도구만 사용했으며 실제 실행 결과는 Codex가 검증한다. 구독 사용률 비중은 추정하지 않는다.
