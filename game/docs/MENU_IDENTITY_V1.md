# 한 그릇의 개성과 실제 판매

실제로 시식한 그릇에는 재료 그림과 짧은 맛의 특징, 시식 점수가 높은 손님을
모은 카드가 나온다. 그 메뉴를 팔면 판매 결과에도 같은 특징을 표시하고,
이번 영업에서 많이 주문한 손님을 보여 준다. 사용자가 붙인 메뉴 이름은 유지한다.

## 화면에서 하는 일

1. 원재료 육수·면과 토핑으로 그릇을 만들고 기존 시식을 완료한다. 완료 순간에
   카드의 그림과 글이 짧게 나타난다. 카드 전체를 누르면 실제 그릇·이름·원가·
   준비 시간을 읽는다. 자세한 손님 평과 개량·탐색의 기존 경로도 그대로다.
2. 카드의 ‘시식 점수’는 실제 평가 결과다. 동점이면 함께 표시하며 0점을 좋은
   반응으로 포장하지 않는다. 다른 손님 선택·다시 열기에는 발견 연출이 재생되지 않는다.
3. 영업 결과의 메뉴 카드에서도 그릇의 특징을 본다. 메뉴를 열면 판매한 음식과
   ‘많이 주문한 손님’을 보여 준다. 시식 점수가 높은 손님과 주문을 많이 한
   손님은 같다고 가정하지 않는다. 일반 손님에게 단골 초상을 붙이지 않는다.
4. 판매 카드의 화살표로 그릇의 개성을, ‘판매 영수증·손님 보기’로 전체 금액·
   손님별 완료 주문·기록이 있는 평균 대기를 펼친다. 뒤로는 해당 메뉴로 돌아간다.

## 표시의 근거

맛의 제목과 최대 두 특징은 기존 연구 방향·맛 프로필의 기준을 사용한다.
매운맛·진함·면 식감·맑고 향긋한 성격을 설명하며, 반복 토핑·배합·공법이
실제 평가에 반영된다. 이 설명은 새 점수·희귀도·보너스·독립 요리 수가 아니다.
모든 배합에 고유한 이름이나 그림이 생긴다고 하지 않는다. 이름·가격·토핑 순서만
달라져도 새로운 맛의 성격을 얻는 식으로 분량을 늘리지 않는다.

현재 편집한 초안 대신 당시 시식 기록과 실제 판매 구성을 읽는다. 판매 금액은
완료 주문으로만 집계한다. 메뉴의 ‘재료비를 뺀 금액’에 공통 하루 운영비를
임의로 나눠 넣지 않으며, 전체 순이익은 기존 영업 결과에 남는다. 주문 0건에는
많이 주문한 손님이나 평균 대기를 만들지 않는다. 옛 단일 메뉴 영수증에 구성이
없으면 없다고 표시한다. 현재 초안이나 비슷한 이름으로 복원하지 않는다.

## 실제 확인과 한계

맑은 다시마·생강/가는 면, 진한 뼈 육수/굵은 면, 얼큰한 닭 육수/고추기름을
각각 실제로 제조·시식·판매했다. 세 그릇의 특징과 선호 손님이 구분되는지,
이후 초안 수정과 저장 복원이 과거 표시를 바꾸지 않는지 확인했다. 각 영업의
날짜도 다르므로 판매량 차이를 마지막 재료 변경의 인과적 효과라고 단정하지 않는다.

Claude는 순수 판단·네이티브 카드·집중 시험과 관찰한 작은 면 그림의 보정을,
Codex는 기존 시식/판매 화면 연결·깊이·읽기 전용 이동·실제 캡처·독립 검증을
맡았다. 파일은 순서대로 작성했다. Claude의 완료 보고를 테스트 통과로 세지 않았다.

기존 도메인·서비스·자산·경제·저장 스키마18은 유지한다. 새 식재료나 캠페인
분량을 추가한 작업은 아니다. 자동 시험은 일부 제조·시식·영업 시간을 앞당겼다.
사람이 느끼는 발견의 재미·연출 음질·6~10시간 본편·최신 iPhone 수용은 별도다.
