# 항구에서 구해 직접 개발하는 라멘

2026-10-22 · Codex 단독 구현. 사용자가 다시 지시할 때까지 Claude 위임은 중지한다.

## 플레이 흐름

1. 등급 2에서 항구의 기존 공급처 두 곳(조개 맑은탕·새우유)을 발견한다.
2. 탐색의 항구 연구 재료 채집에서 재료 설명·보관량·비용을 확인한다.
3. 출발비 1,200원을 낸다. 모든 공급처 탐색·장터 채집과 합쳐 하루 한 번이다.
4. 구운 정어리 육수 또는 가리비 고명을 고른다.
5. 직접 손질해 1개(추가 0원), 손질을 부탁해 3개(추가 600원) 중 고른다.
6. 결과를 직접 수령한다. 대기 중에는 재고가 없으며 두 번 받을 수 없다.
7. 수령 카드의 '이 재료로 실험'으로 개발의 해당 재료 선택을 펼친다.
8. 직접 조합하고 시식한다. 실제 맛·원가·준비 시간과 손님 반응을 확인해 개정한다.
9. 등록 메뉴를 판매하고 다음 날 다시 채집한다.

이동은 기존 항구 도트와 이동 진행 표시를 사용한다. 수령에는 재료 아이콘과 수량 효과,
동적 버튼에는 기존의 누름·클릭 효과가 적용된다. 스와이프로 취소한 터치는 확정되지 않는다.
재료의 상세는 아이콘·화살표가 있는 카드 전체를 눌러 펼친다.
아직 항구가 열리지 않은 초반에는 장터를 먼저 보여주고 항구는 짧은 다음 목표로 표시한다.

## 두 재료의 차이

| 재료 | 맛에 더하는 값 | 한 그릇 원가 | 준비 시간 |
| --- | --- | --- | --- |
| 구운 정어리 육수 | 진함 +1, 간 +2, 향 +5 | 450원 | 30초 |
| 가리비 고명 한 분량 | 진함 +2, 향 +1 | 550원 | 16초 |

값은 재료 자체의 기여다. 완성 메뉴는 다른 재료·공법·익힘과 함께 기존 평가기로 계산하며
맛 축의 상한도 적용된다. 향·진함이 높다고 모든 손님의 점수가 오르는 것은 아니다.
같은 가리비를 3칸 쓰면 연구 재료 3개와 세 분량의 원가·시간이 든다.
새 재료가 없는 기존 구성의 점수·원가·시간은 바꾸지 않는다.

## 재고와 저장

각 재료는 20개까지 보관한다. 샘플은 시제품이 성공적으로 완성될 때 넣은 분량만큼 소모한다.
시식 준비 취소·중복 시식 거부·재료 부족에는 돈이나 샘플을 쓰지 않는다.
장터와 항구 재료를 같이 쓴 시식도 두 재고를 모두 확인한 후 한 번에 반영한다.
등록 메뉴의 판매는 기존 영업 원가로 공급하므로 연구 재고가 0이어도 가능하다.

수령 전 재시작하면 같은 선택/결과로 돌아온다. 포기해도 낸 돈과 그날 출발 기회는 돌아오지 않는다.
수령 뒤의 개발 이동은 현재 초안·메뉴·가격·돈·재고를 변경하지 않는다. 자동으로 재료를 끼워 넣지 않는다.

저장 스키마는 13이다. v1~12는 해당 버전의 구조·규칙을 먼저 검증한 뒤 빈 항구 재고로 옮긴다.
첫 저장은 원본 버전의 바이트를 별도 백업하며 기존 백업은 덮어쓰지 않는다.
새 필드를 옛 버전에 끼워 넣거나 옛 기록에 항구 연구 재료를 섞으면 거부한다.
지역별 재고 보존, 경로별 비용·수량, 공급처 발견일, 지역 간 출발일 충돌,
노트를 정리한 뒤 남은 비교·최고 성적 증빙의 실제 소비량도 검증한다.
이 검사는 로컬 저장의 일관성 검사이며 암호학적 변조 방지 기능은 아니다.

## 검증과 디자인 기준

Product Design의 흐름 점검 기준을 적용했다: 비용을 먼저 알려주기, 결과 수령을 분리하기,
현재 재고 표시, 문맥이 이어지는 개발 이동, 초반에 사용할 수 없는 정보를 접어두기,
기존 글꼴·종이색·주홍/청록 의미색·도트 자산과 스크롤 조작 유지.

현재 검증 증거와 실제 화면의 확인 여부는 [검증 기록](../../evidence/harbor-foraging-v1.json)에 구분한다.
자동 배치 검사·상태 검사가 실제 렌더링이나 iPhone 사용감 검증을 대신하지 않는다.
신선한 Mac 화면 캡처로 잠김·재료 상세·이동·사건·수령·개발·시식의 가로/세로 흐름을 확인한 뒤
Product Design 화면 평가를 작성한다. 기존 캡처를 이번 기능의 화면 증거로 사용하지 않는다.
iPhone 설치와 실기기 평가는 사용자 요청대로 연기한다.

hard square pixels, no blur or realistic photo details. Built-in ImageGen used; no API credential access.
