2026-10-20 · **사용자 검토용 초안, 범위 확정 전.** 현재 구현 기준은 공개 main `d068d8e`다. 이 문서는 개발 방향과 완료 조건을 정하며, 새 기능 구현·스토어 제출·출시 일정의 승인을 뜻하지 않는다. [기존 설계 기준](GAMEPLAY_BLUEPRINT.md), [실제 플레이 검증 계획](PLAYTEST_PLAN.md), [이번 작업 계약](../../tasks/release-scope-v1.md).

## 1. 만들 게임과 본편의 끝

**손님의 요구를 해석해 라멘을 개발하고, 직원을 성장시키며 동네의 대표 라멘집이 되는 싱글플레이 경영 게임.** 메뉴를 고쳐야 할 이유가 사람·가게의 병목·골목의 변화에서 생기고, 바꾼 결과를 그릇·영업·인물의 변화로 확인한다.

사용자 확정 방향은 라멘 중심의 깊은 메뉴 개발, 도전적인 직원 육성, 손님 이야기, 가게 확장·재화 사용·랭크·탐색·대회·작은 사건, iPhone 우선이다. 탐색은 `지역 선택 → 선택형 사건 → 재료 획득`이다. 카이로소프트 작품은 사용자가 좋아하는 경험의 참고이며, 코드·캐릭터·이미지·UI를 복제하지 않는다.

권장 본편 종료는 **최종 가게 등급 심사 + 대표 메뉴 출품 + 주요 인물의 마무리와 골목 행사**다. 메뉴 개발·직원 역할·관계·골목 투자가 마지막 목표에 실제로 쓰여야 한다. 돈이나 영업 횟수만 쌓아 끝나는 조건으로 만들지 않는다. 엔딩 이후에는 기존 가게에서 개발·영업·선택형 도전을 계속할 수 있게 하는 안을 권장한다. 모든 대화 분기·수집을 엔딩 필수 조건으로 강제하지 않는다.

본편 길이는 제작할 콘텐츠의 목표이며, 현실 시간 타이머나 반복 영업으로 채울 분량이 아니다. 게임일 수는 시식·탐색·조작에 걸리는 실제 시간을 관찰한 뒤 조정한다. 본편 길이와 엔딩 후 운영 포함 여부는 아래 선택을 확정한 뒤 기준으로 삼는다.

## 2. 먼저 선택할 두 가지

| 결정 | 권장 초안 | 다른 선택이 바꾸는 범위 | 상태 |
| --- | --- | --- | --- |
| 도시의 비중 | 직접 운영하는 라멘집1곳 + 주변 고정 부지4곳의 작은 골목 | 작은 동네 자유 배치는 배치·길찾기·저장·터치 편집 추가. 자유 도시/다점포는 지도·점포별 경제·관리 흐름부터 재설계 | 사용자 답변 대기 |
| 본편 길이 | 첫 엔딩6~10시간 목표 + 엔딩 후 자유 운영 | 2~4시간은 성장 단계와 사건 수 축소.15~20시간 이상은 수요 변화·후반 도전·사건 변주를 늘려 반복을 검증 | 사용자 답변 대기 |

아래 수량은 **위 권장안에 대한 콘텐츠 예산 제안**이다. 사용자 선택이 다르면 다시 산정한다. 답변이 없다고 추천이 승인된 것으로 처리하지 않는다. 수량을 맞추는 것만으로 범위를 완료 처리하지 않는다.

범위 설명의 `재료`는 육수/타레/향미유/면/토핑의 고유 항목을 뜻하며 익힘 정도나 공법 조합을 새 식재료로 세지 않는다. 현재 고유 식재료는22종(기본16+탐색6)이며 익힘3단계와 공법9조합은 별개다. 기존 재료/메뉴를 삭제해 새 목표에 맞추지 않는다.

단골 예산은6명×2방향×3장=작성·검증할 분기 장면36개이며, 한 저장에서 한 방향씩 선택하면18장을 경험한다. 양쪽 방향을 다 완료해야 엔딩을 볼 수 있게 만들지 않는다. 작은 사건20개는 단골36장·탐색12개·대회5개와 중복 집계하지 않는다. 잡지3편은 사건20개 안에 포함한다. 골목4곳은 직영 라멘 점포4곳이라는 뜻이 아니다.

화면의 도트 간판은 그릇·김·문양으로 표현하고 한글을 직접 도트 그림에 넣지 않는다. 읽어야 하는 이름·설명은 UI 텍스트로 제공한다. 국물·면·시식·훈련 등 시간이 드는 작업에는 시작/진행/완료를 구분하는 연출과 중복 입력 방지를 두고, 실제 영업 시간과 짧은 제작 연출 시간을 구분한다. 단골 시식평에는 작은 인물 초상을 유지한다. 이는 기존 사용자 피드백의 완료 조건이며 최종 아트 정리에서도 빠뜨리지 않는다.

개발 과제12개는 레시피 정답12개를 외우는 목록이 아니다. 기존 연구6개를 포함해 목표·힌트·평가 결과를 보고 여러 조합으로 해결하는 과제다. 탐색 선택의 모든 가지를 사건 한 개씩 세거나, 이름만 다른 재료를 볼륨으로 내세우지 않는다.

## 4. 1차 완성판에서 제외할 것

다음은 권장 보류 범위이며, 사용자 방향 결정에 따라 다시 검토한다.

- 자유 도로·대규모 도시 시뮬레이션, 여러 직영 라멘 점포 동시 운영, 직원의 점포 간 이동.
- 전투 던전·액션 전투, 모든 재료의 유한 재고와 강제 수급, 별도 공장·복잡한 물류.
- 온라인 경쟁·멀티플레이·서버 계정·클라우드 동기화·소셜 기능.
- 광고·가챠·유료 재화·실시간 장기 대기·결제형 건너뛰기. 판매 방식/가격은 출시 준비 때 별도 결정.
- 전체 가구의 자유 배치 편집, 카메라 자유 회전,3D 전환, 대량의 장식 수집.
- Android 동시 출시, 여러 언어 동시 출시. 우선 한국어/iPhone, Mac은 개발·검증용으로 유지.

사건·직원·시설 수를 늘리기 위해 새 관리 시스템을 계속 추가하지 않는다. 예를 들어 계절 한 장면을 위해 날짜/날씨/재고/부패를 한꺼번에 도입하지 않는다.

| 출시물 | 버전·저장 정책·알려진 제한이 명확한 재현 가능한 iPhone 빌드, 아이콘/소개/실제 화면/권리·배포 자료 준비 |

지원 대상 iPhone과 최소 OS·성능 수치, 중단 시 영업의 복귀 정책은 **콘텐츠 대량 제작 전에** 정한다. 실제 현재는 미완료 영업이 영업 전으로 돌아간다. 유지할지 진행을 보존할지 결정하고 화면 안내·중복 정산·배터리/메모리 처리를 함께 검증한다. Mac 세로 캡처 통과를 iPhone 통과로 계산하지 않는다.

플레이 길이는 가설을 승인받은 뒤 외부 설명을 최소화한 관찰로 확인한다. 가능하면 프로젝트에 익숙하지 않은 플레이어도 포함한다. 자동 검사 수나 한 명의 취향만으로 보편적인 재미를 증명하지 않는다. 스토어 제출·계정/서명/상품 설정은 실제 출시 준비에서 별도 실행 범위를 확인한다.

## 6. 개발 순서와 중단 기준

S2의 직원·골목은 먼저 작은 묶음으로 검증하고 나머지 수량을 늘린다. S1은 완성된 콘텐츠를 기다리지 않는다. 각 단계는 코드가 있다고 끝나지 않으며, 설계/구현/통합/실제 기기/플레이 검증의 상태를 분리한다. 일정은 범위와 기술 위험이 정리된 뒤 추정하며 지금 임의의 완료 날짜를 약속하지 않는다.

## 7. 변경 요청과 진척 관리

새 아이디어는 `본편의 어떤 판단을 개선하는가 → 새로 생기는 구현/저장/UI/자산/검증 → 기존 범위 중 무엇을 줄이거나 후속으로 미룰 것인가`를 기록한 뒤 채택한다. 기능을 추가하며 기존 완료 기준을 계속 미루지 않는다. 데이터/저장 구조를 바꾸는 제안은 콘텐츠 추가 전에 작은 계약으로 검증한다.

진척은 우선 위 단계와 시스템별 통과 상태로 보고한다. 이전의30~40%는 주관적 평가였고 확정 범위의 완료율로 사용하지 않는다. 범위 합의 후에만 남은 작업과 위험을 나누어 추정하고, 자동 검사 개수를 진척의 분모로 쓰지 않는다. 본편 완료와 출시 품질 완료도 따로 표시한다.

## 8. 현재 출발점

현재 공개 빌드는 메뉴 개발·연구·탐색·대회/잡지·보조 육성·증축/두 메뉴·세 단골 분기·노트·투자 안내가 연결된 Mac 프로토타입이다. 실제 Mac17,612확인/실패0/206캡처와 새40장 검토는 [실행 증거](../../evidence/investment-native-v2-20261020.json)에 있다. 이는 본편 분량·실제 iPhone·사람의 재미 검증 완료가 아니다.

[35일 직원 진단](STAFF_GROWTH_AUDIT.md)은 속도/절약의 실제 대기·반응·일당 차이를 보여 주지만 초보자 진행 속도를 측정하지 않았다. [14일 투자 진단](CAMPAIGN_AUDIT.md)도 알려진 조합의 통제 실험이다. 이 근거를 다음 작은 도전/경제/목표 설계에 사용하고, 현재3랭크/4직원에 새 수치를 덮어써 과거 저장을 잃게 하지 않는다.
