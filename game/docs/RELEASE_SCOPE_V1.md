## 1. 만들 게임과 본편의 끝

**재료를 파밍하고 실험해 다양한 라멘을 발견하며, 직원·손님·골목과 함께 동네 대표 라멘집으로 성장하는 싱글플레이 경영 게임.** 사용자는 메뉴 개발을 특히 재미있게 만들고, 그 안에 재료 파밍과 재료에 따른 수많은 결과물을 포함하길 명시했다. 핵심 투자 우선순위는 재료 획득→실험→발견이며, 직원·사연·골목은 새로운 재료와 메뉴 개발의 동기·결과를 제공한다.

사용자 확정 방향은 라멘 중심의 깊은 메뉴 개발, 도전적인 직원 육성, 손님 이야기, 가게 확장·재화 사용·랭크·탐색·대회·작은 사건, iPhone 우선이다. 탐색은 `지역 선택 → 선택형 사건 → 재료 획득`이다. 카이로소프트 작품은 사용자가 좋아하는 경험의 참고이며, 코드·캐릭터·이미지·UI를 복제하지 않는다.

권장 본편 종료는 **최종 가게 등급 심사 + 대표 메뉴 출품 + 주요 인물의 마무리와 골목 행사**다. 메뉴 개발·직원 역할·관계·골목 투자가 마지막 목표에 실제로 쓰여야 한다. 돈이나 영업 횟수만 쌓아 끝나는 조건으로 만들지 않는다. **엔딩 후 자유 운영은 사용자 확정 범위**이며, 기존 가게에서 개발·영업·선택형 도전을 계속하는 세부안을 제안한다. 모든 대화 분기·수집을 엔딩 필수 조건으로 강제하지 않는다.

본편6~10시간은 사용자와 합의한 콘텐츠 길이 목표이며, 현실 시간 타이머나 반복 영업으로 채울 분량이 아니다. 게임일 수는 시식·탐색·조작에 걸리는 실제 시간을 관찰한 뒤 조정한다. 모든 플레이어의 소요 시간을 보장하거나 본편이 끝나면 가게 운영을 닫는 기준으로 쓰지 않는다.

## 4. 메뉴 개발·파밍의 중심 설계

이 절의 **핵심 우선순위와 반복 파밍·다양한 결과물은 사용자 요구**다. 혼합 슬롯·고유 품질·발견 도감 등 아래 확대 설계는 제안이다. 첫 작은 구현은 장터 반복 채집/두 연구 재료/시제품마다 샘플1개/등록 메뉴의 통상 원가 공급으로 제한했다. 기존 기본16+발견6을 유지한24종 카탈로그와 실제 Mac 검증을 완료했지만 전체 파밍 분량이나 본편의 재미를 완료 처리하지 않는다. [현재 계약과 상태](../../tasks/market-foraging-v1.md).

권장 순환은 `개발하고 싶은 라멘의 단서 → 지역과 탐색 선택 → 재료 획득 → 배합/공법 실험 → 시식과 새 결과 발견 → 판매·사연·대회로 확인 → 다음 파밍 목표`다. 영업과 골목은 이 순환에 새 수요·공급자·제작 선택을 더한다. 메뉴를 개발하기 위해 목록의 숫자만 올리는 구조로 만들지 않는다.

| 실험과 발견 | 재료·궁합·배합·공법이 맛 계열과 조리 특성을 바꿈. 육수의 주재료/보조재료 조합 등은 작은 별도 실험으로 검증 | 재료 하나를 바꾼 이유와 결과를 이해하고 의외의 유효한 조합을 발견 |
| 결과물의 다양성 | 국물 색/농도·면/토핑 모양·풍미/식감 태그·영업 특성이 서로 연결됨 | 두 결과를 이름/점수를 가려도 구별할 근거가 있음. 수많은 고유 수작업 그림 제작을 약속하지 않음 |
| 다시 개발할 이유 | 도감/발견 기록·다른 손님·가격/원가·대회/행사 수요. 레시피 정답을 처음부터 전부 공개하지 않음 | 한 조합이 모든 목적의 최고가 아니고 같은 재료로 다른 해답을 시도 |

파밍이 영업과 모든 실험을 막는 숙제가 되지 않도록 **기존 기본 재료의 영구 공급을 유지하고, 파밍 재료의 연구용 소비와 레시피 채택 후 공급 방식**을 우선 비교 설계한다. 첫 두 재료는 완성된 시제품에만 각1개를 쓰고 취소/거부에는 쓰지 않으며, 재고가 없어도 등록 메뉴를 통상 영업 원가로 판매하도록 구현했다. 이 한정 규칙의 재미를 확인한 뒤 다른 재료군의 규칙을 정한다. 모든 영업 그릇마다 강제로 캐게 하거나 전체 재료를 소모품으로 바꾸는 승인은 아니다. 재료 부족 시 이유와 대안을 표시하고 숨겨진 자동 소모를 두지 않는다.

처음부터 산지·신선도·품질·등급·속성·숙성의 모든 조합을 추가하지 않는다. 하나의 재료 차이가 새 판단을 만드는 작은 묶음부터 확인한다. 맛 태그나 레시피 계열의 정리 정책도 기존 lineage/개정 이력과 별도로 검토한다. 같은 재료의 이름/가격만 바꾼 개정을 새 요리 발견으로 세지 않는다. 현재 가격 변경이 새 구성으로 취급되는 저장/사연 규칙은 이 문서에서 바꾸지 않는다.

기존 재료30종/과제12개라는 제안 수치는 재미의 최소 증명이 아니다. 먼저 제한된 재료 묶음에서 파밍 선택과 구별되는 라멘 결과가 반복해서 나오고, 그 결과를 다시 팔거나 개량하고 싶은지 확인한다. 그다음6~10시간에 필요한 재료군·발견·과제를 산정한다. 사용자가 요청한 볼륨을 단순한 조합 수 곱셈으로 보고하지 않는다.

## 5. 1차 완성판에서 제외할 것

자유 도시·다점포 동시 운영은 사용자가 선택한 이번 큰 범위에서 제외한다. 나머지는 1차 완성판의 집중도를 위한 권장 보류 범위이며 변경 시 영향을 검토한다.

- 자유 도로·대규모 도시 시뮬레이션, 여러 직영 라멘 점포 동시 운영, 직원의 점포 간 이동.
- 전투 던전·액션 전투, 모든 재료의 유한 재고와 강제 수급, 별도 공장·복잡한 물류.
- 온라인 경쟁·멀티플레이·서버 계정·클라우드 동기화·소셜 기능.
- 광고·가챠·유료 재화·실시간 장기 대기·결제형 건너뛰기. 판매 방식/가격은 출시 준비 때 별도 결정.
- 전체 가구의 자유 배치 편집, 카메라 자유 회전,3D 전환, 대량의 장식 수집.
- Android 동시 출시, 여러 언어 동시 출시. 우선 한국어/iPhone, Mac은 개발·검증용으로 유지.

사건·직원·시설 수를 늘리기 위해 새 관리 시스템을 계속 추가하지 않는다. 예를 들어 계절 한 장면을 위해 날짜/날씨/재고/부패를 한꺼번에 도입하지 않는다.

## 8. 변경 요청과 진척 관리

새 아이디어는 `본편의 어떤 판단을 개선하는가 → 새로 생기는 구현/저장/UI/자산/검증 → 기존 범위 중 무엇을 줄이거나 후속으로 미룰 것인가`를 기록한 뒤 채택한다. 기능을 추가하며 기존 완료 기준을 계속 미루지 않는다. 데이터/저장 구조를 바꾸는 제안은 콘텐츠 추가 전에 작은 계약으로 검증한다.

진척은 우선 위 단계와 시스템별 통과 상태로 보고한다. 이전의30~40%는 주관적 평가였고 확정 범위의 완료율로 사용하지 않는다. 범위 합의 후에만 남은 작업과 위험을 나누어 추정하고, 자동 검사 개수를 진척의 분모로 쓰지 않는다. 본편 완료와 출시 품질 완료도 따로 표시한다.

## 9. 현재 출발점

현재 구현은 메뉴 개발·연구·탐색·대회/잡지·보조 육성·증축/두 메뉴·세 단골 분기·노트·투자 안내에 장터 반복 채집/연구 재료2종을 연결한 Mac 프로토타입이다. 실제 Mac18,214확인/실패0/228캡처와 새22장 검토는 [실행 증거](../../evidence/market-foraging-v1.json)에 있다. S2의 첫 작은 연결을 구현·통합한 단계이며, 본편 분량·실제 iPhone·사람의 재미 검증 완료가 아니다.

[35일 직원 진단](STAFF_GROWTH_AUDIT.md)은 속도/절약의 실제 대기·반응·일당 차이를 보여 주지만 초보자 진행 속도를 측정하지 않았다. [14일 투자 진단](CAMPAIGN_AUDIT.md)도 알려진 조합의 통제 실험이다. 이 근거를 다음 작은 도전/경제/목표 설계에 사용하고, 현재3랭크/4직원에 새 수치를 덮어써 과거 저장을 잃게 하지 않는다.
