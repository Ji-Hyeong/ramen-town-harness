# 중단·복귀 시 저장되는 상태 확인

2026-11-02. 현재 main의 실제 저장·완료 경로를 독립 실행한 진단이다.
게임 동작·UI·저장 형식은 바꾸지 않았다. 승인된 452개 실행 파일과 내용이 같다.
실제 iPhone의 백그라운드 전환이나 강제 종료를 시험한 결과는 아니다.

| 진행 중인 작업 | 같은 실행에서 복귀 | 저장본으로 다시 시작 |
|---|---|---|
| 육수·제면 | 남은 작업을 계속하고 완료 시 한 번 결제 | 미완료 작업 취소, 비용 차감 없음 |
| 시식 | 완료 시 한 번 결제·기록 | 미완료 시식 취소, 비용·결과 추가 없음 |
| 영업 | 같은 주문 진행을 유지하고 최종 정산 한 번 | 정산 전 상태로 복귀, 중간 매출 추가 없음 |
| 재료 탐색 | 선택한 유료 경로 유지 | 지불한 비용·선택 유지, 보상 한 번 수령 |

완료된 육수와 면은 여전히 사용자가 그릇에 적용해야 한다. 백그라운드 저장이
실제 쓰기 충돌로 실패한 경우에도 기존 저장 파일은 보존되고 실패 안내가 남는다.
충돌을 해소하고 작업을 완료하면 전체 확정 상태가 자동 저장되고 안내가 해제된다.

영업은 실제 주문 1건이 완료됐지만 아직 정산하지 않은 시점에서 확인했다.
같은 실행에서 계속하면 최종 9그릇·순수익 63,960원이 한 번 정산됐다.
탐색은 실제 장터 선택에 1,900원을 지불한 후 재시작해 유자 표본 5개를 받았고,
추가 비용이나 중복 수령은 발생하지 않았다. 이 수치는 해당 고정 시험 경로의 값이다.

## 확인 방법과 한계

격리된 저장 위치를 준비한 실제 메인 장면에만 `APPLICATION_PAUSED` 알림을
전달했다. macOS 전체나 다른 창에는 알림을 보내지 않았다. 실제 저장 파일을
별도 재시작 폴더에 복사해 정상 시작·파싱 경로로 전체 저장 값을 비교했다.
제조·시식·영업 시계는 앞당겼다. 화면 렌더링과 운영체제의 중단 동작은 제외했다.

최종 두 실행은 각각 6경로·197확인·실패0·종료0이며 엔진 오류·경고도 없다.
저장·백업·보고서 20쌍이 바이트 단위로 같다. 기존 출력 위치는 쓰기 전에 종료2로
거부하고 20파일의 목록·내용을 보존했다. 첫 실행의 시험 장면 초기화와 주문 대기
상한 문제는 시험 도구에서 수정했다. 실패 로그도 보존하며 게임 수정으로 주장하지 않는다.

```sh
Godot --headless --path game --script res://tools/audit_mobile_pause.gd -- --out-dir=<새로운_절대_폴더>
```

Godot의 [모바일 중단 처리 문서](https://github.com/godotengine/godot-docs/blob/4.7/tutorials/inputs/handling_quit_requests.rst)는
백그라운드 앱이 종료될 수 있음을 설명한다. 이 진단은 실제 iOS의 알림 전달,
저장 완료 시간, 앱 강제 종료·복구, 발열·성능이나 최종 UX 수용을 증명하지 않는다.
실기기 검증에서는 해당 항목을 별도로 확인해야 한다.
