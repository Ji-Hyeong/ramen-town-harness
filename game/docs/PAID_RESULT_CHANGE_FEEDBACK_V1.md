# 시식 직후 개량의 변화를 짧게 읽기

2026-10-30 개발본. 기존 시식 결과의 `이번 개량의 변화` 버튼 제목을 실제 변화로
바꾼다. 새 카드나 긴 설명을 추가하지 않고, 같은 48px 버튼을 누르면 기존 전후
그릇·수치·평가 상세가 열린다. **승인한 전후 앱의 실제 Mac 그래픽 실행과
세 화면 크기의 캡처 검토를 완료했다.**

| 실제 유료 개정 | 결과 버튼 |
|---|---|
| 돼지뼈2분량 → 3분량, 같은 맛/원가+480원/기본 준비+24초 | 맛 같고 부담 늘어요 |
| 반대 방향의 유료 개정 | 맛 같고 부담 줄어요 |
| 맛 지표가 바뀐 육수·면 개정 | 맛이 달라졌어요 |
| 가격만 바꾼 유료 개정 | 맛·원가·준비 그대로 |
| 첫 시식 | 비교 버튼 없음 |
| 정확한 두 레시피 중 하나라도 지식 미확인 | 기존 일반 제목 유지 |

판정은 이미 검증한 `RecipeChangeSummary`를 재사용한다. 현재 배합이나 현재
선택한 메뉴를 기준으로 삼지 않고, 실제 유료 기록 안의 이전 구성과 이번 구성을
비교한다. 이전 기록을 지워도 개정 기록에 남은 복사본을 사용한다. 현재 손님별
맛 점수·풍미·궁합이 모두 같아야 같은 맛이다. 가격 평가는 기존 손님 상세에 남는다.
확인하지 않은 레시피의 미래 평가를 새 제목으로 공개하지 않는다.

선택 목표·발견 안내의 우선순위, 인물 초상·이유·가격 반응, 버튼 눌림과 스크롤
취소, 기존 비교 상세는 유지한다. 경영 규칙·저장19·자산을 바꾸지 않았다.

## 완료한 검증과 한계

Codex가 직접 구현·독립 검증했다. Claude와 다른 에이전트 호출은0이다.

- 실제 새 게임에서 원재료 제조·선택·유료 시식한 개정들을 같은 드라이버로
  실행: 수정 전/후 각365검사 통과. 390×844, 390×750, 1280×800 배치다.
- 첫 기록, 부담/절약, 변경 육수/면, 가격 변경, 나중의 다른 배합, 이전 원본
  삭제 후 보존된 개정, 디스크 재시작을 확인했다. 읽기 동작은 자금·배합·노트·
  지식을 바꾸지 않으며 전후12개 전체 상태 파일도 같다.
- 지식을 숨기는 방어 시험은 별도의 합성 호스트다. 이를 자연 진행에서 만든
  미확인 유료 시식이라고 주장하지 않는다. 실제 진행 증거와 파일을 분리한다.
- 기존 순수/실제 요약436검사, 선택 목표884검사, 첫 메뉴 여정359검사,
  앱 생성기24시험 통과. 모든 실행 종료0이며 엔진/스크립트 오류·경고는0이다.
- 위 배치 시험은 명시적인 headless/layout-only다. 이후 별도 실제 OpenGL
  실행에서 수정 전/후 각각455검사·30PNG·실패0·종료0을 확인했다. 전체60장을
  전후 검토했으며 짧은 제목의 여백·눌림 대비·기존 상세에서 새 결함이 없었다.
  실제 실행의 전체 상태12파일도 같고 실행 후 엄격 엔진 서명도 유효하다.
  iPhone·사람의 재미나 본편6~10시간을 검증한 것으로 세지 않는다.
- 두 준비 앱은 각각442소스와 PCK를 동결했고 공식 엔진 엄격 서명을 확인했다.
  수정 전의 기존440소스는 main df3741c와 같고 시험2파일만 추가했다. 수정 후의
  기존 파일 변경은 시식 버튼을 그리는 `bowl_workbench.gd` 하나뿐이다.
