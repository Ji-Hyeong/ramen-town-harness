# 서버 성장 · 두 메뉴의 점심

2026-10-29 개발본. 기본 서버에게 한 단계의 역할 도전을 추가했다.
메뉴를 두 종류 개발하고 함께 운영하는 목표이며, 새 직원이나 자동 보상은 없다.
**최종v5의 실제 Mac 렌더링 검증을 완료했다.** 가로·세로·짧은 세로881검사/실패0,
원본36장을 검토했다. [선택 원본8장](uiux-reset/server-lunch-challenge-v1/)을 보존했다.
iPhone 설치와 사람의 재미·본편 분량 수용은 이번 작업에 포함하지 않는다.

## 플레이 흐름

1. 2랭크에서 가게를 증축하고 실제 판매 메뉴 두 종류를 지정한다.
2. 직원 화면의 서버 카드를 열어 무료로 도전을 수락한다.
3. 수락 때 판매하던 두 구성 모두와 다른 새 메뉴 두 종류를 유료 시식한다.
4. 두 새 메뉴를 판매 목록에 지정하고 실제 영업을 끝까지 마친다.
5. 정산 화면에서 서버 도전으로 이동해 달성 여부를 보고, 직접 성장을 받는다.

서버 카드에는 짧은 진행 안내와 성장 효과를 먼저 보여준다. 여섯 조건은
눌러 펼치고, 시도 후에는 실제 메뉴별 판매량·평균 대기·만족도를 읽는다.
메뉴 개발 버튼과 판매 메뉴 확인 버튼은 기존 화면으로 연결된다.
기본 직원 그림과 기존 음식·프레임을 재사용했다. 사용자 선택 시안의 서체·색을
유지하며 모든 직원 카드의 자식 글씨도 누르는 동안 흰색으로 바뀐다.
드래그 취소 후에는 원래 색으로 돌아간다.

## 한 번의 영업에서 필요한 조건

| 조건 | 판정 근거 |
|---|---|
| 수락 후 두 메뉴 모두 새 구성으로 시식 | 새 기록 번호·시식일·가격을 제외한 구성 |
| 각 메뉴 3그릇 이상 | 실제 완료 주문의 메뉴 번호별 개수 |
| 합계 8그릇 이상 | 같은 영업의 실제 완료 주문 |
| 평균 대기 150초 이하 | 완료 주문 대기 합계 ÷ 완료 그릇 |
| 평균 만족도 3.5/5 이상 | 완료 주문 별점 합계 ×2 ≥ 완료 그릇 ×7 |
| 두 메뉴 모두 10,000원 이하 | 영업한 두 메뉴의 실제 판매 가격 |

가격만 바꾸기, 이전 메뉴를 다시 팔기, 한 메뉴만 개량하기, 개량한 뒤 늦게
수락하기로는 새 개발 조건을 채우지 못한다. 두 새 구성도 서로 달라야 한다.
면·육수 원재료 배합과 제조 방식은 구성 비교에 포함한다.
시식·예측·계산용 `serve()`·한 메뉴 영업·중단은 이 도전의 증거를 만들지 않는다.
첫 달성 영업은 이후 실패나 노트 삭제로 덮어쓰지 않는다. 수락은 초기화할 수 없다.

## 성장 효과와 한계

성장을 직접 받은 다음 영업부터 기본 서버의 서빙·복귀 시간에 각각80%를
적용한다. 보조 직원 효과를 먼저 올림한 뒤 다시 올림하고 최소1초를 유지한다.
기존 요리사 숙련·보조 자격과 함께 저장되지만 조리 시간·맛·수요·일당·자금·
직원 칸은 바꾸지 않는다. 같은 성장을 반복해서 받을 수 없다.

정수 단위 올림 때문에 짧은 동선은 실제로 줄지 않을 수 있다. 실제로 같은
원재료 메뉴·영업일을 맞춘 다음 날 비교에서:

| 직원 구성 | 도전 미수령 / 수령 후 완료 주문 | 평균 대기(게임 초) | 평균 별점 |
|---|---:|---:|---:|
| 보조 없음 | 10 / 10 | 136.9 → 134.9 | 3.7 → 3.7 |
| 숙련 홀 보조 | 10 / 10 | 132.9 → 131.9 | 3.7 → 3.7 |

두 구성 모두 실제 주문 흐름과 대기가 달라졌다. 완료 주문 수와 별점은 같았으므로
추가 매출·만족도 향상을 주장하지 않는다. 처음10% 시안은 숙련 홀 보조의 짧은
동선에서 효과가 사라져20%로 조정했다. 같은 메뉴와 영업일을 유지해 다시 비교했다. 이 비교는 실제 공개 동작으로 받은 도전/자격을 사용했지만,
가속한 자동 영업이며 사람의 플레이 시간이나 재미·난이도 평가가 아니다.

## 저장·분담·검증

저장19에 `server_challenge`를 추가했다. 실제 이전 저장18은 빈 도전으로
이행하며 기존 자금·일차·배합·노트·연구·자격·영업 보고를 보존한다. 최초 저장 시
이전 파일의 원문 백업도 남긴다. 과거 보고에 새 숙련을 소급하지 않는다.
손상 상태는 명시적 오류로 거부하며 초기화해 성공한 것처럼 처리하지 않는다.

- Claude: 순수 도전 규칙과 집중 시험. 첫 호출 성공42턴, 같은 작업 수정5턴;
  요청 제한은 각각30/10턴이었다. 둘 다 종료0·success·오류없음·권한 거절없음을
  확인했고, Codex가 실제 코드를 검토·실행했다.
- Codex: 상태/저장19·시간 효과·화면/정산 연결·독립 시험·호환성 검증.
  Claude 최종 소유 파일 두 개의 해시는 통합 이후 그대로 유지했다.
- 집중 시험1,272개, 기존130묶음60,730개, 레시피 기억4,138개,
  부품 비교373개, 제면276개, 육수226개, QA 생성기24개 통과. 기존 직원 성장690개·요리사 도전784개 배치 검사도 통과.
- 이전 main의 실제 저장18을11개 생성(99검사), 새 코드로 이행122검사 통과.
  별도 비교도 전체 기존 값·원문 백업·원본 해시11개 모두 같았다.
- 원재료 실제 경계12경우203검사, 별도 읽기 전용 검증307검사 통과.
  같은 토핑이라도 다른 원재료 기반 두 메뉴는 달성했고, 노리3분량은 만족도,
  차슈2분량은 대기, 고가 메뉴는 가격·주문량 조건에서 미달했다.
- 실제 숙련 전후2쌍78검사와 전체 상태 디스크 재시작 통과.
- v5 묶음430파일의 원본 일치, 공식 엔진 엄격 서명, 화면 배치773검사 통과.
  이후 실제 렌더러에서도881검사/실패0·종료0·엔진/스크립트 오류0을 확인했다.
  v2 배치는 없는 아이콘 오류로 폐기했으며,
  수정한 v5의 배치·부품 시험 로그에서는 엔진/스크립트 오류가 없었다.
