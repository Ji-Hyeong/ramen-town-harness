# 확인한 메뉴의 변화부터 짧게 읽기

2026-10-29 개발본. 육수·면 완성 목록의 비교 화면에서 개량의 결과를 짧게 먼저
보여주고, 실제 전후 수치는 눌러 펼친다. 기존 음식 그림·서체·카드·고정 행동은
유지했다. **현재 실제 렌더링은 수정 전/후 QA 앱의 실행 승인 대기다.**

## 무엇이 달라졌나

기존에는 원가·시간 수치를 읽고 손님별 점수를 비교해야 변화의 의미를 알 수
있었다. 이제 비교 카드의 제목과 한 줄 차이로 먼저 읽는다.

| 확인한 현재 그릇의 결과 | 먼저 보이는 안내 |
|---|---|
| 맛 지표 같음, 원가·준비 같음 | 맛·원가·준비 그대로 |
| 맛 지표 같음, 부담 증가 | 맛 같고 부담 늘어요 |
| 맛 지표 같음, 원가/준비 절약 | 맛 같고 부담 줄어요 |
| 원가·시간 중 하나는 증가, 다른 하나는 감소 | 맛 같고 원가·시간 교환 |
| 실제 맛 지표가 달라짐 | 맛이 달라졌어요 |
| 둘 중 하나라도 아직 모르는 레시피 | 담은 뒤 맛 비교 |

예를 들어 확인한 돼지뼈2분량→3분량 비교에서는 **맛 같고 부담 늘어요**와
**원가+480원 · 기본 준비+24초**를 먼저 읽는다. 헤더 전체를 누르면 현재 그릇
기준이라는 설명과 정확한 전후 수치를 펼친다. 드래그하면 펼치지 않고 스크롤하며,
누르고 있는 동안 제목과 숫자도 흰색으로 바뀐다.

맛 같음은 풍미5축·궁합 합계·현재 손님3명의 개별 점수·평균이 모두 같은 경우다.
평균만 같다고 같은 맛으로 표시하지 않는다. 이는 현재 완성 그릇의 수치 비교이며
다른 토핑/타레/손님에게도 같거나 레시피가 불필요하다는 뜻은 아니다.
상한 도달 같은 원인을 관찰 없이 만들어내지 않는다.

## 직접 담기 전에는 맛을 미리 말하지 않는다

현재 그릇과 후보 그릇을 둘 다 직접 선택해 확인했을 때만 같음/달라짐을 말한다.
완성 육수나 면을 제조·비교 목록에서 보기만 해서는 그 전체 라멘을 알게 되지 않는다.
새 요약은 미확인 비교의 제목·펼친 설명·반환 데이터에서도 궁합·단골 점수·맛 동일 여부를
공개하지 않는다. 기존에 공개하던 원가·기본 준비 차이는 그대로 읽을 수 있다.

그릇에 담기·배합 불러오기·제작·결제는 기존 명시적 버튼만 수행한다.
보기·펼치기·스크롤은 자금·날짜·배합·노트·레시피 지식·저장 내용을 바꾸지 않는다.
새 저장 필드, 재료, 평가 규칙이나 상한 변경은 없다.

## 분담과 검증 범위

Claude가 순수 결과 요약과 집중 시험을 작성했고, Codex가 범위/손님 집합 검증을
독립 검토해 수정 요청한 뒤 기존 화면·실제 제조/선택·저장 시험을 연결했다.
최종 Claude 소유2파일은 통합 이후 그대로다. 사용자가 Claude 호출을 줄이라고
한 시점에는 세 호출이 모두 끝난 상태였으며 이후 추가 호출 없이 Codex가 진행했다.

- 실제 새 게임에서 제조·선택·유료 시식한 시험 데이터37검사 통과.
- 순수/실제 통합436검사, 레시피 지식4,138검사, 부품 비교373검사 통과.
- 세 크기의 새 화면 배치329검사, 수정 전248검사, 기존 비교 화면315검사 통과.
  이는 실제 렌더링 검증이 아니다. 최종 로그의 엔진/스크립트 오류·경고는0이다.
- 같은 실제 동작의 전후 저장/단계 스냅샷15개 전체 값이 같았다.
- 수정 전은 승인된430게임 파일을 그대로 보존하고 시험4파일만 추가했다.
  수정 후는440파일이며 기존430개 중 수정한 파일은 비교를 그리는 화면 하나뿐이다.
  모든 경영 규칙·저장19·기존 자산은 그대로다.
- 초기 검토에서 불가능한 음수 풍미/잘못된 손님 집합을 받아들이는 요약 검증을
  보완했다. 의도한 NaN 시험의 JSON 스냅샷이 null로 바뀌는 문제도 시험 쪽에서
  비유한 값을 구분하는 표현으로 수정했고 해당 거절 시험은 유지했다.
