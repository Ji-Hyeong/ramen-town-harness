# 연구 목표를 따라 라멘 실험하기

메뉴 개발을 재료 선택과 숫자 확인에서 한 단계 확장한다. **이번 실험 선택 → 필요한 재료 찾기 → 조합·공법 변경 → 시식 → 노트에서 확인**을 작은 한 묶음으로 연결했다. 기존 토핑2/3/4칸과 동종 분량, 실제 시제품 비용·샘플 소비를 그대로 사용한다.

## 플레이 흐름

- 개발 화면은 현재 재료로 만든 라멘의 특징을 표시한다. 육수·타레·향미유·토핑 분량으로 설명 이름을 만들고, 실제 맛과 공법에서 특징을 붙인다. 플레이어가 정한 메뉴 이름을 자동으로 덮어쓰지 않는다.
- `이번 실험` 카드의 화살표를 눌러 조건과 재료 단서를 읽는다. 첫 목표는 같은 토핑을 두 번 올리는 `토핑 겹쌓기`다. `연구 지도`에서 주제 카드를 펼쳐 다른 목표를 고른다. 목표를 고르는 것만으로 구성·재료·자금·점수는 바뀌지 않는다.
- 아직 발견하지 못한 재료나 현재 시제품에 필요한 채집 샘플이 부족하면 `재료 찾기`로 기존 탐색 화면에 간다. 출발은 직접 골라 확정하며 기존 등급·비용·하루 제한을 적용한다. 화면 이동만으로 출발비를 내지 않는다.
- 개발 화면 하단의 `시식 · 비용`은 재료 목록을 끝까지 내려가지 않아도 누를 수 있다. 기존 시식과 같은 준비·취소·완료 처리를 사용한다. 거부 이유는 이 버튼 옆에 남긴다.
- 기존 시제품을 불러와 바꾸면 맛 실험대에서 **맛 축·원가·준비 시간·판매가의 실제 차이**를 비교한다. 손님 평가를 미리 보장하지 않는다.
- 성공적으로 시식한 뒤 새롭게 맞춘 연구 방향이 있으면 결과에 이름을 공개한다. 가격만 바꿔 같은 방향으로 다시 시식했다고 새 연구로 표시하지 않는다. 목표 조건을 맞췄다는 뜻이며 맛 점수나 현금 보너스가 아니다.

## 여덟 가지 연구 방향

| 방향 | 실험의 초점 | 재료 단서 |
| --- | --- | --- |
| 진국의 깊이 | 돼지뼈 국물의 진함 | 시작 재료와 공법 |
| 맑고 향긋한 한 그릇 | 가벼운 국물과 향의 균형 | 닭·다시·조개 육수 |
| 얼큰한 기름 | 매운 향미유의 활용 | 시작 고추기름·산골 초피유 |
| 면의 힘 | 면·익힘·공법의 식감 | 시작 중간면·굵은 면 |
| 토핑 겹쌓기 | 같은 토핑의 반복 분량 | 시작부터 열린 두 칸 |
| 바다와 산 사이 | 조개 국물과 표고의 조합 | 아침 항구·산골 농가 |
| 유자 향 가벼움 | 채집 고명으로 가볍게 만들기 | 새벽 장터 채집 |
| 고소한 참깨 한 방울 | 채집 향미유로 진함 더하기 | 새벽 장터 채집 |

정확한 레시피 한 개만 정답으로 정하지 않았다. 서로 다른 재료·공법이 같은 방향을 만족할 수 있고, 한 메뉴가 여러 방향에 맞을 수도 있다. 이 여덟 방향을 여덟 개의 별도 시스템이나 완성된 본편 분량으로 세지 않는다.

## 기록과 역할

연구 지도는 **현재 보관 중인 실제 시식 노트**를 정리한 화면이다. 초안을 만들기만 해서는 수록되지 않는다. 해당 연구와 맞는 마지막 기록을 삭제하면 수록 표시도 사라지며, 다른 맞는 기록이 있으면 유지한다. 기존 저장v12를 바꾸지 않아 기존 메뉴·자금·점수·영업·샘플 회계를 그대로 보존한다. 이번 목표 선택은 화면을 위한 임시 선택이고 별도 영구 수집 보상은 추가하지 않았다.

Claude Code가 순수 판정/설명, 관련 시험, 실제 목표·지도 화면 컴포넌트를 구현했다. Codex가 계약·독립 검사·표적 수정 요청, 시식·노트·탐색 연결과 고정 시식 버튼·비교 화면·입력/저장 회귀 검증을 맡았다. 실제 제한 프로필 호출은 두 번이며 종료0·success·오류false·권한 거부0을 확인했다. 코드 반환만으로 통과 처리하지 않았다.

사용자가 iPhone 설치를 뒤로 미뤘으므로 개발을 기기 연결에 묶지 않는다. 실제 렌더링과 기기 검증 상태는 [검증 기록](../VERIFICATION.md), 재현 가능한 작업 범위는 [계약](../../tasks/recipe-discovery-v1.md)을 따른다. 기존 iPhone 설치본과 이전 서명 빌드는 이번 연구 지도 적용본이 아니다.
