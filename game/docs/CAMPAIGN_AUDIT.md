# 14일 연속 영업·투자 점검

2026-10-19 · 로컬 v10 게임 소스 기준. **수치를 바꾸거나 사람이 플레이한 결과가 아니다.** 기존 독립 날짜별 경제 검사에서 확인하지 못한 연속 자금·성장·저장 흐름을 점검했다. 실제 화면과 iPhone 검증은 계속 미완료다.

## 방법

빠른 맑은 라멘(8,500원)과 느린 진한 라멘(10,000원)을 각각 고정 판매했다. 각 메뉴에 무투자/조리대만/증축만/조리 보조/홀 보조/모두 투자라는 여섯 정책을 적용했다. 총12개의 새 게임을14일씩 진행했다. 메뉴 원가와 취향이 다르므로 두 메뉴의 수익 차이를 직원 효과라고 해석하지 않는다. **투자 효과는 같은 메뉴의 무투자 경우와 비교한다.**

모두30,000원·1일차·랭크1에서 시작했다. 실제 공개 편집·시식·연구·승급·구매·고용·훈련 API를 사용했고, 돈·날짜·등급·경험을 주입하지 않았다. 실제 영업 세션을 끝까지 진행하고 완료 주문으로 정산했다. 매일 별도 시험 폴더에 저장한 뒤 새 GameState로 전부 불러와 다음 날을 진행했다. 최종 본 파일은14일차, 백업은13일차 원본과 바이트가 같았다. 사용자 플레이 저장은 사용하지 않았다.

연구는 알려진 정답 조합으로 하루 한 건씩6일에 걸쳐 완료했다. 연구 메뉴는 판매 메뉴와 별개인 한 계열을 계속 개정했다. 모든 정책에 같은 기록 ID·구성·연구 순서·가격을 사용했다. 등급 심사는 실제 조건 충족 뒤4일차/11일차 준비 중 신청했다. 각 정책의 시설과 직원은 조건·자금이 허용하는 즉시 구매하고, 훈련은 실제 경험을 충족할 때만 했다. 조리대 투자는 용량을 열지만 이번 고정 한 메뉴 실험은 추가 토핑/메뉴를 활용하지 않는다.

모두 연구 보상은21,000원 한 번씩뿐이다. 무투자의 시식비는 빠른 메뉴11,020원/느린 메뉴12,050원이고, 순영업 이익은 각각1,020,640원/845,400원이다. 즉 큰 잔액을 연구 보상이나 가짜 시작 자금으로 만든 결과가 아니다. 첫 승급 후4일차 준비 자금은 각각246,460원/206,450원으로, 두 경우 모두 랭크2에서 열린 조리대12,000원+직원 공간15,000원+증축60,000원+조리 보조8,000원을 한꺼번에 살 수 있었다. 직원 두 명을 동시에 고용하지 못하는 제한은 돈보다 직원 공간 단계에 있었다.

느린 메뉴의 조리 보조는4일차 고용 후6일차 끝에 무투자 잔액을 처음 넘어섰고14일차에14그릇을 더 팔았다. 빠른 메뉴는 판매량이 늘지 않아 일당과 투자비만 추가됐다. 입문 훈련은 빠른 메뉴8일차(43그릇/4실무일), 느린 메뉴9일차(48그릇/5실무일)에 가능했다.14일차 조리 보조 경험은117그릇/106그릇으로 두 경우 모두 전문화160그릇 조건에는 아직 못 미쳤다. 특정 전문화가 불가능하다거나 경험 조건이 너무 높다고 결론 내리지 않는다.

## 해석과 다음 개발 기준

1. **메뉴에 따른 직원 선택은 이미 다르게 작동한다.** 다만 이번 모든 세션의 관측 이탈은0이었다. 느린 메뉴의 추가 판매를 화면에서 관측한 줄 이탈 감소로 설명하면 안 된다. 현재 수요 계산은 조리 시간과 고객 인내 기준으로 방문 의향 자체를 낮추고, 조리 보조는 그 시간도 줄인다. 실제 조리 시간·완료 판매·방문 전 수요와 화면 이탈을 구분하는 안내가 필요하다. 코드 근거는 [수요 계산](../scripts/domain/sales_simulator.gd), [영업 계획](../scripts/domain/service_session.gd)이다.
2. **초반의 저축 압박은 약할 가능성이 더 커졌다.** 알려진 답을 이용하는 이 일정에서는 첫 승급 시점에 가능한 주요 투자를 모두 살 수 있다. 수치를 일괄 올리기 전에, 시설을 사서 무엇을 바꿀지 목표가 보이는지 확인해야 한다. 아직 초보자의 실패 실험·탐색·대회 지출을 포함한 결과는 아니다.
3. **증축·조리대의 가치를 이 표 하나로 부정하지 않는다.** 한 메뉴·한 토핑을 고정했으므로 두 메뉴 판매와 복수 토핑을 활용하지 않았다. 현재 수요에서 좌석 확대만으로 판매가 늘지는 않았다. 다음 비교에서는 새로 열린 용량을 실제 사용한 메뉴 전략을 대조해야 한다.
4. **직원 육성의 다음 개선은 역할별 목표와 결과 해석을 먼저 권장한다.** 단순 경험 숫자 확대나 전 직원 맛 보너스보다, 느린 메뉴 개선·붐비는 날 홀 운영처럼 해결한 문제를 보여주는 방향이다. 이번 작업에서 기본 직원 육성/새 도전/경제 조정은 구현하지 않았다. 실제 화면 확인 후 이 진단을 반영한 한 가지 계약으로 범위를 정한다.

확인된 사실은 연속 거래·재시작의 일관성과 위 두 고정 메뉴의 투자 차이다. 아직 모르는 것은 사람이 선택을 이해하는지, 정답을 모를 때의 성장 속도, 복수 메뉴/토핑·탐색·이야기와 연결한 장기 전략, 재미와 실제 iPhone 조작이다. **다음 판단은 기존 v9/v10 화면 확인 뒤 투자 효과 안내와 역할별 성장 중 한 범위를 정하는 것**이다. 확장 기능을 더 쌓기 전에 이 관찰을 사용한다.

## 검증과 재실행

[실행 도구](../tools/audit_campaign_progression.gd), [독립 검산기](../tools/verify_campaign_audit.py), [선별 증거](../../evidence/campaign-progression-v1.json), [작업 계약](../../tasks/campaign-progression-audit-v1.md).

168회의 실제 영업, 게임 측3,446확인과 별도 Python4,002확인이 실패0·종료0으로 통과했다. Python 최적화 모드에서도 검증은 유지된다. 잘못된 잔액·판매 수·스냅샷을 넣은 세 검산은 각각 종료1로 거부됐다. 기존 출력 폴더를 다시 지정한 엔진 실행은 종료2로 거부했고 기존193개 파일 해시가 전부 보존됐다. 새 도구 외 게임 번들 소스85개는 준비한 QA 스냅샷과 같다. 엔진은 실행 전후 엄격 공급자 서명 검증을 통과했다. 이번 두 정상/거부 실행 로그에는 스크립트·파싱·엔진 오류가 없었다. 이전 다른 실행의 시스템 CA 오류가 고쳐졌다는 일반적 주장은 아니다.

첫 진단 v1은 시험 도구가 개정할 때 이름을 다시 설정해 게임의 정상 거부 규칙에 걸려 종료1로 실패했다. 선택한 기존 이름을 그대로 사용하는 v2로 도구만 수정했고, 게임의 거부 규칙은 바꾸지 않았다. 실패 자료도 로컬에 보존했다.

프로젝트 루트에서 검증된 Godot 실행 파일 경로를 사용한다. 출력 상위 폴더는 존재해야 하며 출력 폴더 자체는 새 경로여야 한다.

```sh
"$RAMEN_GODOT" --headless --path game \
  --script res://tools/audit_campaign_progression.gd -- \
  --out-dir=/private/tmp/ramen-campaign-new-run
python3 -O game/tools/verify_campaign_audit.py /private/tmp/ramen-campaign-new-run
```

`RAMEN_GODOT`은 해당 Mac에서 서명을 확인한 공식 엔진 경로다. 그래픽 앱을 시작하는 명령이 아니며, 이 문서는 앱 실행 승인이나 실기기 검증을 대신하지 않는다.
