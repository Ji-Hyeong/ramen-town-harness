# 장터 메뉴를 손님에게 대접하는 시식회

2026-11-02. 재료 목표와 시식에 그치던 장터 메뉴를 실제 가게 운영에 연결하는
작은 의뢰 하나다. 가게2랭크부터 기존 의뢰 탭에서 `유자 맑은탕`과 `참깨 진국`
중 한 방향을 골라 무료로 수락한다. 선택 후 방향 변경은 없고 현실 시간 제한도 없다.
이미 개발한 메뉴도 쓸 수 있다. 새 요리 발견을 보상하는 시스템은 아니다.

수락 후 **한 번의 실제 영업에서 조건에 맞는 메뉴 한 종류를5그릇 이상,
평균 별3개 이상** 대접하면 답례를 받을 수 있다. 두 메뉴의 수량을 더하거나
날짜를 누적하지 않는다. 시식·예상 매출·즉시 계산 영업·중단/부분 영업·수락 전
영업은 실적이 아니다. 첫 달성 영수증은 이후 다른 영업이나 노트 삭제에도 남는다.

영업 결과의 `시식회 답례 도착 · 의뢰 보기`는 실제 달성 상태에서만 나타나며
의뢰 화면으로 이동한다. 이동만으로 돈을 주지 않는다. 직접 답례를 받으면
5,000원이 한 번 지급되고 다시 받을 수 없다. 재료·지식·맛·수요·연구 점수·랭크·
직원 효과를 추가하지 않는다. 보유 자금 한도/작업 중에는 거래 전체를 거부한다.

기존 종이 카드·음식/탐험 아이콘·큰 버튼·눌림/스크롤 취소·클릭 및 수령 연출을
재사용한다. 조건·실제 메뉴·완료 수량·평균 만족을 보고, 재료/개발과 판매 준비는
기존 상세 화면으로 들어간다. 새 탭이나 가짜 예상 라멘 그림은 추가하지 않았다.

## 저장과 검증

저장20은 수락 방향/일차, 실제 메뉴 구성과 완료 수량/별 합계, 답례 일차만 남긴다.
지원되는1..19저장에는 빈 진행만 추가하고 과거 보상을 소급하지 않는다. 불러오기
전에 모든 필드를 검사하며 남은 메뉴/최근 영수증과 모순되는 증거는 거부한다.
이는 로컬 일관성 검사이고 부정행위 방지 인증은 아니다. 기존 SaveService가
첫20저장 전19원본을 바이트 그대로 백업하는 것을 실제 파일로 확인했다.

- 별도의 합성 방어 입력과 실제로 획득한 원재료/파밍 저장을 이어 간 거래198검사:
  두 요리 방향, 실제 유료 제조/샘플 소비/시식, 단일/확장 영업, 거부의 원자성,
  첫 달성 보존·노트 삭제, 자금 상한·중복 수령·전체 필드 불변과 실제 디스크 재시작.
- 기존 전체130항목/60,730검사, 기존 판매575·서버773·첫 여정359검사 통과.

  결과 화면→수령 이동·지급 후 버튼 잠금·저장 실패/복구·새 장면 재시작 통과.
