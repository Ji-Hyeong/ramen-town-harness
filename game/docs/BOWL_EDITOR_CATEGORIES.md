# 그릇 중심 개발 화면: 선택과 재료 분류

2026-10-23. 사용자는 실제 표시 순서3번 `concept-03-map.png`를 선택했다.
상단 육수·면 요약과 토핑별 가격·조리시간·상세보기를 좋아하며,
향후 토핑 증가에 대비한 분류를 요구했다. 원래 세 시안을 다시 고르는
단계가 아니다. 선택한 구조에 분류를 넣은 **수정 이미지**를 만들었다.
아직 네이티브 게임에 적용한 화면이나 터치 검증 결과는 아니다.

## 유지하는 선택

- 상단에서 육수·타레·향미유와 면·익힘을 함께 확인한다. 해당 그룹을
  누르면 그 목적의 편집으로 들어가며 긴 전체 양식을 다시 펼치지 않는다.
- 그릇은 현재 조합을 나타낸다. 토핑은 실제 랭크의 칸 수와 반복 분량을
  보여주며, 추가·교체·빼기를 구분한다.
- 재료 행에는 그림, 이름, 분량당 가격과 준비시간을 표시한다.
  `+`는 한 분량 추가, 별도 정보 아이콘은 상세보기다. 정보 확인은 재료를
  추가하거나 비용을 지불하는 동작이 아니다.

## 많은 토핑을 위한 목록

그릇과 조합 정보, 분류, 시식 동작은 고정하고 **재료 행 목록만 스크롤**한다.
화면 전체를 긴 문서처럼 밀어야 하거나 작은 스크롤바를 잡아야 하는 구조로
돌아가지 않는다. 행·그림·버튼 위에서 시작한 스와이프도 목록에 전달한다.
취소된 누름이 추가나 상세 열기로 확정되어서는 안 된다.

분류 제안은 한 줄의 `전체 / 고기·달걀 / 채소·과일 / 해산물`이다.
이는 재료를 탐색하기 위한 UI 분류로, 맛·비용·해금·재고 규칙을 바꾸지 않는다.

| 분류 | 현재 카탈로그의 대응 재료 |
| --- | --- |
| 고기·달걀 | 차슈, 반숙란 |
| 채소·과일 | 숙주·파채, 절임 무, 표고 조림, 유자 껍질 |
| 해산물 | 김, 가리비 고명 |

`해산물`에는 해조류도 포함한다. 필요하면 출시 전 이름을 `해산물·해조`로
다듬을 수 있으나, 긴 탭 이름 때문에 터치 영역을 줄이지 않는다.
카테고리는 한 재료가 여러 분류에 중복되어 보이지 않도록 정의한다.
새 재료 추가 시 해당 분류를 명시해야 하며 임의의 기타 분류로 숨기지 않는다.
미발견·샘플 부족은 기존 잠금 상태를 유지한다. 분류가 보인다고 재료가
획득되거나 선택 가능해지는 것은 아니다.

## 상태 보존과 상세 깊이

- 분류 전환은 담아둔 토핑·선택 칸·비용·자금을 바꾸지 않는다.
  각 분류의 스크롤 위치는 그 화면을 사용하는 동안 기억한다.
- 상세는 짧은 설명, 분량당 추가 원가/준비시간, 현재 확보 상태와 실제
  획득처에 집중한다. 닫으면 같은 분류와 목록 위치로 돌아온다.
- 목록의 초는 해당 재료 한 분량이 더하는 영업 준비시간이다.
  시제품 조리 연출의 실제 경과 초나 완성 그릇 전체의 준비시간과 혼동하지 않는다.
  시식 비용은 현재 조합 전체의 실제 계산값으로 갱신한다.
- 한도 가득 참·잠금·조리 중·입력 취소를 구분해 반응한다. 정보/추가/분류
  버튼에는 서로 겹치지 않는 최소44px 터치 영역을 네이티브 구현에서 확보한다.

## 수정 이미지와 검증 경계

[분류를 넣은 수정본](uiux-reset/refinements/concept-03-categories-v1.png)은
원래3번 이미지를 실제 입력으로 첨부해 내장 Image Gen의 독립1회 수정으로
생성했다. 새로 세 방향을 제안한 것이 아니다. 원본은853×1844,
목표 논리 화면은390×844이며 리사이즈·잘라내기 없이 보관한다.
원본/프롬프트/선택한 입력의 해시는 [기록](uiux-reset/refinements/manifest.json)에 있다.

실제 버튼 크기, 분류 전환, 스크롤, 그림과 실제 재료의 일치, 전체 조합 편집,
조리·시식 결과는 구현과 실행으로 검증해야 한다. 수정 이미지의 버튼을
측정 없이44px라고 주장하거나 이미지를 게임 수정 완료로 보고하지 않는다.
현재 게임 코드·저장·아이폰 설치본 변경은 없고 Claude 호출도 없다.
