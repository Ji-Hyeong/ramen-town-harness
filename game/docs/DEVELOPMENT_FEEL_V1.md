# 토핑 분량과 메뉴 개발 연출

## 토핑을 칸에 담기

사용자가 선택한 시작 용량은 **등급1에서2칸 → 등급2에서3칸 → 등급3에서4칸**이다. 등급을 올리면 자동으로 열리며 토핑을 위해 조리대를 추가 구매할 필요가 없다. 조리대는 기존 가격으로 등록 메뉴 종류를6→12→30종 늘린다. 직원 공간과 승급 조건은 기존 규칙을 따른다.

- 재료 버튼을 누르면 빈 칸에 한 몫을 추가한다. 차슈+반숙란처럼 섞거나 차슈+차슈처럼 같은 종류를 여러 칸에 담을 수 있다.
- 교체하려면 담긴 칸을 먼저 누르고 재료를 고른다. 가득 찬 상태에서 재료 버튼만 누르면 거부하며 기존 토핑을 몰래 빼지 않는다.
- 칸 옆의 `−`는 그 칸의 한 몫만 뺀다. 최소 한 몫은 남겨야 한다.
- 잠긴 칸에는 필요한 가게 등급을 표시한다. 재료 버튼의 `×2` 같은 표시는 해당 재료를 담은 분량이다.

한 몫마다 실제 원가·준비 시간·맛 축을 더한다. 예를 들어 차슈를 한 몫 더 넣으면 기존보다700원/15초가 늘어난다. 맛 축은 기존처럼0~10으로 제한하고 동일 궁합의 보너스를 중복 적립하지 않는다. 많이 넣는 것과 좋은 메뉴를 만드는 것은 다르며 손님마다 선호와 가격 반응이 다르다.

채집 재료도 분량대로 쓴다. 유자 껍질을 두 칸 넣은 시제품은 완성할 때 샘플2개를 소비한다. 한 개만 남았다면 시식이 거부되며 일부 샘플·자금·기록을 먼저 차감하지 않는다. 제조 취소에도 샘플은 줄지 않는다. 이미 등록한 메뉴의 영업은 이전처럼 샘플을 추가 소비하지 않고 그 메뉴의 실제 영업 원가를 적용한다.

## 실험과 반응

개발 화면의 맛 실험대는 현재 그릇의 진함·짠맛·향·면 식감·매운맛을 실제 프로필 막대로 보여준다. 궁합 메모도 실제 평가 규칙에서 가져온다. 이것은 손님 점수나 보너스를 미리 확정하는 화면이 아니다.

재료를 추가·교체하면 아이콘과 불꽃 조각이 튀고 실제로 달라진 맛 축 또는 새 궁합을 짧게 보여준다. 일반 버튼은 작은 클릭 효과, 재료 투입·제조 단계·시제품 완성은 더 큰 효과로 구분한다. iOS에서는 큰 효과에 짧은 진동도 연결한다. 효과는 화면 입력을 받지 않고 사라지며 돈·점수·기록을 바꾸지 않는다. 스와이프로 취소된 버튼은 클릭 효과도 만들지 않는다.

국물→면→시식 단계가 바뀔 때 작업 카드에서 반응하며, 완성되면 **실제로 보이는 시식 탭**의 그릇과 손님 카드를 차례로 공개한다. 이전 코드는 숨겨진 개발 탭의 그릇을 튀겨 효과가 보이지 않았다. 반복 시식 때는 이전 스크롤 위치와 무관하게 결과 맨 위로 돌아온다. 강제 화면 흔들기나 조작 대상 이동은 사용하지 않는다.

## 저장과 검증 범위

저장v12는 같은 종류의 토핑 분량과 새 등급 용량을 허용한다. 이전1~11은 기존 값을 유지해 읽고, 새로 저장하기 전에 해당 버전의 원본을 보관한다. 이전 스키마에 중복 토핑이나4칸 구성을 주입한 파일은 거부하며 과거 조리대 용량 조건도 그 버전 규칙으로 먼저 검사한다. 불변 메뉴/삭제된 기록의 증빙도 샘플 소비 분량을 확인하되 같은 기록을 여러 번 참조했다고 중복 소비로 세지 않는다.

원본v11 코드로 만든 저장8종을 이행해 기존 모든 값과 원본 백업의 바이트 일치를 비교했다. 이전 메뉴974가지의 평가·그릇 픽셀도 동일했다. 분량·원자적 실패·현재 저장 왕복, 실제 입력 경로의 스크롤/탭, 두 화면 크기와 연출 캡처는 별도로 검사한다. 실행 결과와 실제 기기 설치 상태는 [검증 기록](../VERIFICATION.md)에 기록한다. 자동 검사를 재미나 사용자의 최종 조작감 승인으로 대신하지 않는다.
