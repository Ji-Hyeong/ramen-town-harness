# 원재료부터 만드는 육수 개발

2026-10-27. 사용자가 완성 육수 선택만 있는 구조를 거부해 추가한 핵심 개발 흐름이다.
새 게임은 완성 육수를 받지 않는다. `육수 개발하기 → 원재료 배합 → 우림 방식 → 실제 우림 → 완성 육수 선택 → 면·타레·향미유·토핑 → 시식` 순서로 진행한다.

## 직접 만드는 것

- 시작 공급처: 돼지뼈, 닭뼈, 다시마, 양파, 생강, 마늘. 기본 원재료는 개발비/그릇 원가로 공급하며 매 영업 그릇마다 채집을 강요하지 않는다.
- 공급처 발견: 항구 바지락, 산골 말린 표고. 기존 실제 탐색의 공급처 발견을 조건으로 사용한다.
- 연구 채집: 항구 구운 정어리. 한 배합에 한 분량이며 라멘 시제품이 성공적으로 완성될 때 기존 장부에서 샘플1개를 쓴다. 우림에서 중복 소모하지 않는다. 샘플0개라면 새 정어리 육수 개발도 시작할 수 없다. 채택한 메뉴의 영업은 기존 통상 원가 공급을 유지한다.
- 랭크1/2/3에서 배합3/4/5칸. 같은 원재료를 여러 분량 넣을 수 있으며 분량마다 비용·준비 시간이 합산된다. 주재료 없이 향채만으로는 완성할 수 없다.
- 기본/약불/강불 우림. 강불은 랭크2부터. 약불은 진함을 낮추고 향을 올리며 비용/시간이 늘어난다. 강불은 반대 성격의 교환을 만든다.

각 완성 육수는 원재료와 우림 방식으로 저장된다. 맛·원가·준비 시간은 매번 같은 계산으로 재구성하며 저장 파일의 임의 점수를 신뢰하지 않는다. 그릇의 국물 색도 실제 배합의 진함에 반응한다. 기존 그릇/토핑 원본 그림은 바꾸지 않는다. 뼈·향채·해산물 아이콘은 새로 그린 코드 기반 도트다.

원재료 궁합에는 돼지뼈+닭뼈의 겹맛과 다시마+표고의 향 조합이 있다. 각각 추가 준비 시간/원가를 동반하며 무조건적인 점수 보너스를 주지 않는다. 실제 고객 평가는 기존 라멘 평가기를 사용한다. 모든 배합이 독립적인 새 요리나 고유 이미지가 된다고 주장하지 않는다.

## 조작과 시간

배합과 개발한 육수 목록을 별도 깊이로 나눈다. 원재료 분류, 성질/공급처 상세, 추가/한 분량 제거, 고정된 주행동을 제공한다. 재료 변경 때 선택 목록의 스크롤을 유지한다. 우림 중에는 재료 편집 목록을 치우고 움직이는 솥·진행 단계·취소에 집중한다. 실제 프레임 시간으로 약5~6.5초를 진행하며 화면을 누르는 것만으로 완료하지 않는다.

완성 때 개발비를 한 번 낸다. 취소·중복 시작/완료에는 비용이나 제품이 추가되지 않는다. 완성 육수는 최대60종 보관하고 명시적으로 선택해 라멘에 사용한다. 현재 라멘의 육수는 배합을 편집하는 것만으로 교체되지 않는다. 완성 육수의 우림 공법을 라멘 화면에서 따로 바꾸는 대신 개발실에서 다른 배합/공법으로 실험한다.

## 저장과 기존 게임

스키마16은 미완성 배합과 완성 육수 기록을 보존한다. 우림 진행률은 임시 상태다. 종료/재시작 시 배합은 남고 끝나지 않은 우림은 취소되며 개발비/제품을 지급하지 않는다. 완료 후 자동 저장이 거부되면 화면에 알리고 수동 저장으로 재시도할 수 있다. 저장 재시도는 다시 우려내거나 중복 결제하지 않는다.

v1~15 저장의 기존 메뉴·초안·평가·잔고·영업·연구 진행은 그대로 읽는다. 기존 육수는 이전 저장 호환용이며 새 게임에는 주지 않는다. 이전 기록을 새로 만든 육수라고 위조하거나 과거 점수를 재계산하지 않는다. 첫 v16 저장 전에 기존 버전의 원본 파일을 별도 백업한다.

과거 기능 시험은 실제 v15 이행을 거친 `legacy_game_fixture.gd`를 명시적으로 사용한다. 새 게임 의무 개발 검사는 `game_state.gd`를 직접 사용해 우회 없이 검사한다. 동결한 main `cc64e5a`의 수정하지 않은 v15 엔진 실행에서 만든 `tests/fixtures/broth-v15-save.json`으로 기록/잔고/보고 보존과 원본 바이트 백업을 별도 검증한다.

## 검증 범위와 제한

새 게임에서 원재료 육수만으로 여섯 연구 의뢰, 실제 영업과 랭크3까지 도달하는 공개 거래 경로를 검사한다. 세 가지 실제 배합의 차이, 정어리 채집/시제품 소비, 잠금·취소·중복·중첩 저장 변조와 재시작을 검사한다. Mac의 두 화면 크기에서 실제 입력·렌더링·저장 거부/재시도를 별도로 확인한다. 최종 결과는 [선별 증거](../../evidence/raw-broth-development-v1.json)에 기록한다.

이번 작업은 육수 개발 첫 구현이다. 원재료 제면, 타레/향미유 자체 제조, 대량 생산 재고, 장시간 오프라인 숙성, 전체 본편의 재미·난이도 검증은 완료 범위가 아니다. 아이폰 설치본0.15를 이 작업에서 자동 갱신하지 않는다.

공식 레퍼런스는 [카이로소프트 라멘가게 소개](https://kairosoft.net/game/appli/noodle.html)의 제면·육수 제작을 포함하는 개발 방향을 확인했다. 여기의 원재료 수치·배합 규칙·랭크 칸수·그림은 우리 게임의 설계이며 원작의 수치나 제작 경험을 재현했다고 주장하지 않는다.
