# 원재료 제면 개발 V1

면을 완제품 목록에서 고르던 흐름을 **가루·배합수 → 굵기 → 반죽·숙성 → 제면 → 완성 면 선택**으로 바꾼다. 기존 육수 개발과 연결하며 새 게임은 두 부품을 모두 만들어 그릇에 넣은 뒤 처음 시식한다.

| 선택 | 내용 | 실제 변화 |
| --- | --- | --- |
| 가루 | 중력 밀가루 / 강력 밀가루 / 산메밀 배합분 | 원가, 식감, 향 |
| 배합수 | 맑은 배합수 / 간수 배합수 | 원가, 탄력 |
| 굵기 | 가는 직면 / 중간 물결면 / 굵은 꼬불면 | 식감, 삶는 시간, 원가, 기존 국물 궁합 |
| 반죽·숙성 | 기본35% / 고가수40% / 저가수30% 숙성 | 식감과 향의 장단점, 원가, 시간 |

가수율은 이번 버전에서 반죽 방식에 묶인 세 단계다. 연속 슬라이더나 현실 제면 시뮬레이션은 아니다. 랭크1에서24개, 랭크2에서36개, 산골 채집까지 연 랭크3에서54개의 배합을 만들 수 있다. 서로 다른 배합이 모두 전용 그림이나 전용 발견 이벤트를 갖는다는 뜻은 아니다. 현재 그릇 그림은 기존 면 종류의 표현을 재사용한다.

제면은 실제 프레임 시간으로5~7초 진행한다. 선택만으로 지출하거나 완제품을 주지 않는다. 완료할 때 개발비를 한 번 내고, 완성 면 목록에서 직접 선택해야 그릇에 반영된다. 완성 배합을 다시 개발해 중복 결제하는 행동은 막고 기존 배합을 재사용한다. 재시작 시 미완성 작업은 취소되며 저장한 배합은 유지된다. 완성 시 저장이 실패하면 경고를 표시하고 직접 저장으로 재시도할 수 있다.

산메밀 배합분은 기존 산골의 샘플 장부와 연결한다. 제면 시 샘플을 별도로 또 쓰지 않고, 라멘 시식이 성공할 때 기존 규칙대로1개를 쓴다. 등록 메뉴 영업은 기존 통상 원가 공급 규칙을 따른다. 채집 출처에서 개발로 이동하면 원재료 목록을 열며, 완제품으로 자동 교체하지 않는다.

저장 버전은17이다. v1~16의 메뉴·육수 배합·시식 기록·영업 보고·재화는 유지하고 제면 기록을 소급 생성하지 않는다. 과거 저장의 완제품 면은 호환된다. 실제로 이전 main285fad5에서 생성한 v16 저장을 고정 fixture로 사용하며, 새 버전 첫 저장 전 원본 바이트를 버전별 보관본으로 남기는지 검사한다. 옛 테스트는 명시적 호환 fixture를 사용하고 새 게임 검증은 현재 생성자를 사용해 두 개발 과정과 여섯 연구·랭크3까지 실제 거래로 진행한다.

UI는 선택한 기존 그릇 편집기의 프레임·글꼴·금색 행동 버튼을 유지한다. 네 배합 항목은 각각 눌러 상세 선택으로 들어가며 목록과 주요 행동 버튼은 분리한다. 카드·버튼 위의 밀기는 스크롤되고, 취소된 밀기는 선택이나 클릭 이펙트를 남기지 않는다. 제면 연출은 솥에서 면을 삶는 그림과 구분한 독자적인 도트 작업판이다.

검증 결과와 실제 화면은 [화면 기록](uiux-reset/raw-noodle-development-v1/README.md), 저장소 루트의 `evidence/raw-noodle-development-v1.json`에 기록한다. Mac 자동 입력과 렌더링 검사는 실제 iPhone 터치·음향·수명주기 검사와 구분한다. 이번 작업에는 iPhone 설치가 포함되지 않는다.

최종 검증: 새 제면276개·기존 육수226개·기존 도메인129개 테스트/59,458개 검사를 통과했다. 동일347개 소스와 패키지에서 실제 화면 검사는 제면291개·육수235개·편집기528개, 총80장 캡처로 마쳤다. 터치 이벤트 회귀49개와 QA 도구23개도 통과했다. 최종 실행은 모두 종료0이며 엔진 오류가 없고, 실행 뒤 공식 엔진의 엄격 서명 검사를 통과했다.
