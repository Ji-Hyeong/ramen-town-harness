# 초기 플레이와 경제 검증 계획

2026-10-17 · **검사 계획이며 실행 결과가 아니다.** 기능 자동 검사, 실제 렌더링 검사, 사람이 느끼는 재미를 각각 기록한다. 사용자가 외출 중인 현재에는 사용자 플레이를 완료했다고 표시하지 않는다.

## 목적과 준비

[설계 기준](GAMEPLAY_BLUEPRINT.md)의 가설을 검증한다. 목표는 초반 30분 안에 메뉴 개발 → 영업 → 결과 해석 → 다음 목표가 연결되는지, 10게임일 동안 의미 없는 반복이나 압도적인 단일 전략이 있는지 확인하는 것이다.

테스트용 새 저장만 쓴다. 빌드 커밋/저장 스키마/화면 크기/입력 방식/테스트 날짜를 기록한다. 현재 공개 v8과 네이티브 미검증 v9의 결과를 섞지 않는다. 기존 사용자 저장으로 경제 실험을 하지 않는다. 이 문서의 체크리스트만으로 새 로컬 앱 실행 권한이 생기는 것은 아니다.

## A. 첫 30분: 설명을 최소화한 관찰

| 과제 | 볼 것 | 기록할 것 |
| --- | --- | --- |
| 처음 화면 보기 | 식당 경영이라는 목적과 다음 행동을 찾는가 | 첫 의미 있는 행동까지 시간, 잘못 누른 화면 |
| 한 손님을 정해 메뉴 만들기 | 취향 단서를 찾고 원하는 요소를 바꾸는가 | 목표 손님, 변경 요소, 예상 결과 |
| 시식 후 한 번 개정하기 | 점수보다 원인을 이해하는가 | 전/후 조합, 시식 횟수, 변경 이유를 자신의 말로 설명했는지 |
| 영업 한 번 끝내기 | 실제 손님 흐름과 결과를 연결하는가 | 완료 그릇/이탈/이익, 대기의 원인 이해 여부 |
| 다음 목표 고르기 | 탐색·단골·투자 중 스스로 고르는가 | 고른 이유, 필요한 비용·조건을 찾았는지 |
| 저장 후 재개하기 | 저장 완료/실패 표시와 복귀 위치를 이해하는가 | 사용 저장 기능, 잃은 행동 여부, 안내 혼동 |

시간은 안내가 필요한 순간에 잠깐 기록하는 정도로 쓰고, 플레이를 계속 설명하도록 방해하지 않는다. 관찰자는 막힌 조작과 이유를 기록한 뒤 필요한 도움을 준다. 도움 없이 성공한 것과 도움을 받은 성공을 구분한다.

## B. 10게임일: 전략과 투자 비교

자동화 가능한 연속 거래·경제 부분은2026-10-19 [14일 진단](CAMPAIGN_AUDIT.md)으로 먼저 확인했다. 정답을 아는 두 메뉴·여섯 투자 정책이며 아래 사람의 목표 선택/조작 이해도/반복 피로도 관찰을 완료한 것이 아니다.

빠른 점심형, 진한 대표 메뉴형, 특정 손님 특화형의 세 가설을 별도 새 저장에서 비교한다. 각 전략의 목표와 메뉴를 고른 근거를 시작 전에 적고, 모든 전략에 동일한 일수/해금 규칙을 적용한다. 예측상 유리한 조합을 초보자의 자연스러운 선택이라고 간주하지 않는다.

| 매일 적을 항목 | 사용 목적 |
| --- | --- |
| 시작/끝 자금, 영업 이익, 일회성 보상, 시식·투자 지출 | 돈이 어디서 생겼는지 분리; 통장 잔액만으로 메뉴 수익성 판정 금지 |
| 메뉴 계열/개정본/가격, 시식·삭제 횟수 | 실험이 편한지, 노트 용량이 시도를 막는지 확인 |
| 완료 주문·이탈·대기, 사용 직원과 전문성 | 메뉴와 인력의 상충 관계/병목 확인 |
| 랭크 조건과 달성일, 탐색/연구/단골/대회 진행 | 목표 간 연결과 반복 영업 강요 구간 확인 |
| 다음 투자 예상 비용과 구매일, 구입 이유 | 투자 우선순위와 저축 기간이 의미 있는지 확인 |
| 같은 행동만 반복한 날과 이유 | 콘텐츠가 끝난 것인지 UI를 몰라서인지 구분 |

투자 비용 ÷ 해당 전략의 대표 순영업 이익은 참고 지표이며 해금 조건·시제품비·다른 투자 때문에 달라지는 실제 구매일도 함께 기록한다. 투자 전후 수요와 메뉴가 다르면 효과 비교의 한계로 명시한다.

## C. 메뉴 개발과 이야기의 별도 점검

같은 재료에서 공법 하나만 바꿔 예상/관측 변화를 비교한다. 부드러운 식감이나 짧은 조리 시간이 언제 도움이 되는지 플레이어가 설명하는지 본다. 시식 점수·가격·원가·대기 시간이 동시에 좋아지는 사례는 전역 만능인지 특정 조건에서만 좋은지 추가 조사한다.

단골 한 명의 첫 장과 다음 장을 실제 영업으로 이어 본다. 시식만으로 끝났다고 생각하는지, 어떤 메뉴를 그 손님에게 대접해야 하는지 이해하는지, 다음 장을 위해 바꾼 점이 사연에 맞는지 기록한다. 가격 변경만으로 맛 사연을 해결한 경우는 규칙 오류와 별개로 설계 관찰 사항으로 남긴다. 예산 사연의 가격 개선까지 일률적으로 무효로 보지 않는다.

탐색은 한 지역의 공급처를 발견한 뒤 행동할 이유가 남는지 확인한다. 2026-10-23 기준 최초 공급처 발견은 유한 콘텐츠이고, 장터·항구는 별도의 연구 재료4종을 반복 채집할 수 있다. 산골 반복 채집은 아직 없다. 없는 보상을 찾게 만들지 않고, 다음에 만들 메뉴와 실제 필요한 재료 때문에 출발하는지 관찰한다. 새 연구실의 세 방향은 정답 레시피나 영구 보상 도감이 아니므로, 조건을 읽는 것과 실제 유료 시제품을 만드는 것을 구분한다.

## D. iPhone 별도 통과 기준

Mac의 390×844 배치 검사는 실기기 검증을 대체하지 않는다. 실제 iPhone을 사용할 수 있는 시점에만 수행한다.

- 한 손으로 주 메뉴 열기/닫기, 조합 선택, 시식·판매·정산을 수행한다. 오입력과 손가락에 가려진 정보를 기록한다.
- 안전 영역과 키보드를 확인한다. 긴 메뉴 이름·여러 토핑·단골 대사에서도 중요한 버튼과 결과가 가려지지 않아야 한다.
- 준비/제조 중/탐색 선택 중/영업 중/정산 직후에 앱을 중단하고 재개한다. 설계한 복귀 정책과 실제 상태가 일치하고 중복 차감/보상이 없어야 한다.
- 저장 실패·회복 시 사용자에게 남아 있는 행동과 다시 해야 할 행동이 명확해야 한다.
- 연속 영업 시 프레임과 입력 응답, 발열·배터리 문제를 관찰한다. 목표 성능 수치는 대상 기기를 정한 뒤 확정한다.

## E. 다음 개발을 결정하는 기준

| 관찰 | 우선 조치 |
| --- | --- |
| 실험하려다 노트 삭제/정리 때문에 중단 | 실험 이력과 메뉴 용량 분리부터 검증 |
| 첫날부터 투자 대부분을 살 수 있고 목표가 안 바뀜 | 경제와 해금 속도 조율; 일괄 인플레이션 전에 투자 선택 설계 |
| 높은 점수 메뉴 하나를 계속 쓰며 개정 이유가 없음 | 손님 요구·서비스 상황에 따른 목표 차이를 먼저 보강 |
| 직원이 숫자 할인으로만 느껴짐 | 기본 직원의 역할 도전/표현 개선; 레벨 개수부터 늘리지 않음 |
| 가게보다 탭/목록에 오래 머무름 | 주 화면 진입점과 문맥별 안내 조정 |
| 초반 순환과 투자 판단이 이해되고 다음 목표를 스스로 선택 | 골목 부지 두 종류 또는 공급자 사건 중 한 가지로 확장 |

반드시 끝에 남길 결론은 `확인된 문제 / 아직 모르는 점 / 다음에 바꿀 한 가지`다. 한 명의 평가를 보편적 재미로 일반화하지 않는다. 테스트 개수만 많다는 이유로 다음 단계를 통과시키지 않는다.
