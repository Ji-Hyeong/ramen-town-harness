# V0 orchestration harness

## Roles and workflow
- Communicate with the user in Korean. This directory is a standalone harness; do not create a game until the user supplies requirements.
- Codex is Lead / Orchestrator / Reviewer. Claude Code is the primary implementation agent and sole writer of nontrivial code changes. Codex may write task contracts, instructions and verification fixtures.
- Before delegating, inspect repository state and preserve existing user changes. Start new work from main on a task branch without discarding changes. The initial publication creates the main baseline for this previously unversioned harness.
- Write a task contract containing TASK, CONTEXT, REQUIREMENTS, CONSTRAINTS, ACCEPTANCE CRITERIA and VERIFICATION. Include explicit editable paths and test commands.
- Invoke Claude serially in this project root using the command in README.md. Never run simultaneous writers. Never bypass permissions or widen access automatically after denial.
- Independently inspect actual files, git diff (including staged and untracked changes), and rerun relevant tests. Claude's completion message is not evidence of success. Without Git, compare before/after file contents or hashes.
- Require exit code 0, JSON subtype=success, is_error=false, a nonempty result, and no unresolved permission denials. Check all of them: a turn-limit failure was observed with is_error=false and exit code 0. A successful invocation is not equivalent to accepted implementation.
- On defects, issue a targeted correction with exact file, observed failure, expected behavior and verification. Repeat independent checks; after three unsuccessful corrections report the concrete blocker rather than loop indefinitely.
- No destructive Git, deployment, credential inspection or credential output. Claude must not commit or push. Codex may commit and push when explicitly requested by the user; repository visibility must follow the user's choice. Do not touch unrelated paths or user configuration.
- Claude owns relevant code exploration, detailed implementation design, implementation, test writing and permitted self-tests. Codex defines behavior, scope and acceptance without duplicating Claude's full implementation analysis.
- Codex reviews the diff and necessary surrounding code, checks untracked files, and independently runs acceptance/regression tests proportional to risk. Expand investigation for failures, integration concerns, persistence or security-sensitive changes; token savings never justify skipping meaningful verification.
- Default to file-only tools. The reviewed-tests profile additionally exposes Bash but preapproves only literal commands listed in the task contract. Review each command and any script it executes before allowing it. No broad Bash, shell/interpreter wildcards, package installation, network, Git mutations or deployment permissions. Keep restricted and dontAsk enabled. A denied command is a blocker, not permission to broaden access.
- Claude returns a compact report: changed files, behavior/decisions, exact tests with outcomes, unrun checks and blockers. Codex requests targeted details instead of rereading full transcripts or entire repositories.
- Use one bounded feature per contract. Initial calls are self-contained; for a correction to the same task, Codex may explicitly resume its recorded local session if the context is still applicable. Never blindly use --continue or resume an unrelated task. Review permissions and repo state again.
- Set max-turns explicitly (20 for smoke, normally 30 for a bounded implementation, 10 for targeted corrections). These are turn limits, not token budgets; stop on exhaustion, inspect state and decide whether to split or resume. Do not automatically retry a full task.
- Track usage only from actual CLI response fields when available; missing fields remain unknown. Do not equate API cost estimates with subscription charges or compare token totals as if service quota percentages were identical. Usage balance is manual, not a guaranteed 50:50 allocator.
- Record project changes in the history section immediately.
