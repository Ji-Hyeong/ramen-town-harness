# TASK
1차 완성판의 범위·콘텐츠 규모·완료 조건을 검토 가능한 초안으로 정리한다.

## CONTEXT
사용자가 전체 개발 범위를 먼저 정하자고 제안했다. 현재 공개 main d068d8e는 단골v9/노트v10/투자 안내의 실제 Mac 화면 검증을 통과했다. 이전30~40% 평가는 합의한 분모가 없는 주관적 추정이며 진척 기준으로 사용하지 않는다. 골목 비중과 본편 길이는 사용자 선택을 요청한 상태다.

## REQUIREMENTS
- 기존 확정 요구·현재 구현·새 권장 범위를 구분한다. 새 추천을 사용자 승인으로 기록하지 않는다.
- 출시 목표/핵심 순환/포함·제외/콘텐츠 개수/기능별 통과 조건/개발 순서와 범위 변경 규칙을 작성한다.
- 메뉴 개발을 중심으로 직원·손님·골목이 역할을 가지게 하고, 기능 개수·조합 수·테스트 횟수를 재미 지표로 삼지 않는다.
- 사용자 답변 전 골목/플레이 길이는 미확정으로 남기고 큰 선택에 의존하는 구현을 시작하지 않는다. 추천안은 명확히 제안으로 표시한다.
- 현재 상태의 오래된 기획 문구를 정리하되 과거 구현 이력을 보존한다. 문서 간 읽는 순서와 링크를 연결한다.

## CONSTRAINTS
Codex가 기획 문서를 작성한다. 편집은 game/docs/RELEASE_SCOPE_V1.md, GAME_DESIGN.md, game/docs/GAMEPLAY_BLUEPRINT.md의 안내·현황, README.md의 링크, 이 계약, AGENTS.md로 제한한다. 게임 코드/수치/스키마/에셋/플레이 앱/사용자 저장은 변경하거나 실행하지 않는다. 초안은 검토용 로컬 커밋으로 보존하며 합의된 출시 범위처럼 main에 게시하지 않는다. 기간·예산·재미·iPhone 완료를 보장하지 않는다.

## ACCEPTANCE CRITERIA
포함 항목마다 현재와 목표/통과 조건이 구분되고, 콘텐츠 개수는 의도한 목표와 단순 조합 수를 구분한다. 큰 미확정 선택과 후속 제외 항목이 보인다. 본편 종료와 출시 품질 조건이 있으며, 새 기능 계약이 참조할 단일 범위 문서가 생긴다.

## VERIFICATION
현재 기획/플레이테스트/직원 장기 진단/코드 카탈로그와 대조한다. 문서 로컬 링크, git diff --check, 변경 경로·현재 게임87소스/PCK 미변경을 확인한다. 문서만 바꾸므로 게임 테스트/GUI는 다시 실행하지 않는다.

## OUTCOME
검토용 v0.1 초안 완료. 현재와 권장 목표/본편 종료/콘텐츠 예산의 중복 집계 방지/제외 범위/출시 품질/단계·변경 규칙을 정리했다. 현재 식재료16+6=22종을 코드로 확인하고87개 게임 소스 해시 미변경·문서 링크86개·diff 서식 검사를 통과했다. 게임/GUI/사용자 저장은 실행하지 않았다. 골목 비중·플레이 길이는 사용자 답변 대기이며, 범위 합의나 새 기능 구현 완료로 표시하지 않는다. 로컬 초안 커밋만 보존하고 공개 main은 그대로 유지한다.
