# TASK
현재 프로토타입의 핵심 재미와 성장 설계를 점검하고, 큰 재작업을 예방할 기획 기준을 작성한다.

## CONTEXT
사용자는 외출 중이므로 권한 변경이나 실제 플레이를 요청하지 않는다. 기존 단골 이야기 v9는 로컬 기능 검증을 통과했지만 실제 렌더링 검증 전이다. 이번 작업은 그 상태를 완료로 바꾸지 않는다.

## REQUIREMENTS
- 사용자 확정 방향, 현재 구현, 권장 설계를 구분한다.
- 메뉴 실험/직원/탐색/골목/재화/모바일의 연결과 우선순위를 정한다.
- 현재 평가기와 영업 런타임으로 제한된 밸런스 표본을 계산한다. 예측과 실제 완료 주문 계산을 구분하고 재미 검증으로 과장하지 않는다.
- 첫 플레이 검증 절차와 다음 구현의 진입 기준을 남긴다.

## CONSTRAINTS
- Codex가 문서와 진단 도구만 작성한다. 게임 도메인/UI/저장 형식/밸런스 값은 변경하지 않는다.
- 사용자 저장, 원본의 보존 대상 복사본, 인증 정보에 접근하지 않는다.
- 네이티브 앱 실행/서명 우회/새 Claude 호출/공개 PR/머지는 하지 않는다.
- 편집 경로: GAME_DESIGN.md, AGENTS.md, game/DESIGN_DIRECTION.md, game/docs/GAMEPLAY_BLUEPRINT.md, game/docs/PLAYTEST_PLAN.md, game/tools/audit_design_balance.gd, evidence/design-balance-v1.json, 이 계약.

## ACCEPTANCE CRITERIA
- 변경 비용이 큰 결정과 현 상태의 설계 위험에 코드 근거와 권장 조치가 있다.
- 진단은 기본 재료 단일 토핑 972구성, 가격 5개/요일 7개, 공법 9조합을 명시한 범위로 실행한다. 외부 파일 경로를 받아 결과 하나만 쓰며 저장 서비스를 호출하지 않는다.
- 영업 표본은 완료 주문 런타임까지 확인한다. 계산 범위를 전체 게임의 최적 전략으로 부르지 않는다.
- 실기기/재미/실제 화면의 미검증 상태를 유지한다.

## VERIFICATION
Godot --headless --path game --script res://tools/audit_design_balance.gd -- --out=<별도 결과 경로>. 출력·종료 코드·스크립트 오류를 확인하고 독립적으로 결과 구조/합계를 점검한다. 문서 상대 링크와 diff를 확인한다. 문서/진단 도구만 변경하므로 전체 게임 회귀 검사를 반복하지 않는다.

## OUTCOME
- 완료: 플레이 설계 기준/플레이테스트 계획, 기존 기획 문서의 날짜·상태 구분, 진단 도구와 해시 포함 결과 JSON.
- 진단 972구성/34020예측/8748공법/21영업일 표본, 실패0/종료0/스크립트 오류0. 최초 결과에 매출·원가·운영비를 추가해 두 번째 실행했고 표본 값이 일치했다. 독립 Python 확인83개/실패0. 시스템 CA 조회 오류는 별도 기록하며 엔진 오류0으로 과장하지 않는다.
